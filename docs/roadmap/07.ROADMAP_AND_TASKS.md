### 5.2 Nguyên tắc chia Task

**Nguyên tắc cơ bản:**

1. **Task Size**: Mỗi task nên hoàn thành trong **1-2 ngày**
2. **Clear Input/Output**: Task có đầu vào và đầu ra rõ ràng
3. **Minimal Dependencies**: Task không nên phụ thuộc nhiều task khác
4. **Independent Testing**: Task có thể test được độc lập
5. **Vertical Slices**: Ưu tiên vertical slices thay vì horizontal

**Task Breakdown Strategy:**

```
BAD (Horizontal - khó test):
├── Setup PostgreSQL
├── Install .NET packages
├── Create project structure
└── Write configuration

GOOD (Vertical - dễ test):
├── Task-01: Setup Docker + PostgreSQL → Working DB
├── Task-02: .NET project + Entity → Running API
└── Task-03: Auth flow → Login works
```

## 10. Rủi ro và Mitigation

### 10.1 Technical Risks

| Risk | Impact | Probability | Mitigation |
|------|--------|-------------|------------|
| pgvector performance issues | High | Medium | Benchmark early, tune indexes |
| OpenAI API rate limits | Medium | High | Redis caching, batch processing |
| OCR accuracy issues | Medium | Medium | Manual QA, multiple OCR engines |
| LLM response quality | Medium | Medium | Prompt engineering, fine-tuning |
| Large document handling | High | High | Chunking optimization, streaming |

### 10.2 Schedule Risks

| Risk | Impact | Probability | Mitigation |
|------|--------|-------------|------------|
| Complex dependencies | High | High | Parallel development where possible |
| Third-party API changes | Medium | Medium | Abstraction layer, version pinning |
| Resource constraints | Medium | Medium | Prioritize MVP features |
| Testing time underestimated | Medium | High | Buffer time in sprint planning |

### 10.3 Mitigation Strategies

**1. Parallel Development**
```
- Backend và Frontend có thể develop song song
- Mock services cho Frontend khi Backend chưa ready
- Feature flags để enable/disable features
```

**2. API Abstraction**
```
- Interface cho tất cả external services
- Mock implementations cho testing
- Easy switch giữa providers (OpenAI ↔ Azure OpenAI)
```

**3. Incremental Delivery**
```
- MVP sớm (auth + document upload)
- Incremental feature delivery
- Feedback loop với stakeholders
```

**4. Monitoring & Alerting**
```
- Health checks cho all services
- Performance monitoring từ day 1
- Error tracking (Sentry)
- Log aggregation (Seq, ELK)
```
