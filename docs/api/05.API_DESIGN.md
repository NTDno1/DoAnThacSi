## 1. Nguyên tắc Thiết kế API

### 1.1 Quy ước RESTful

Hệ thống tuân thủ nghiêm ngặt các nguyên tắc RESTful (Representational State Transfer) để đảm bảo tính nhất quán và khả năng mở rộng:

| Nguyên tắc | Mô tả | Ví dụ |
|------------|-------|-------|
| **Resource-based URLs** | Sử dụng danh từ số nhiều cho resources | `/api/v1/documents`, `/api/v1/chat/sessions` |
| **HTTP Methods** | Ánh xạ CRUD operations sang HTTP methods | GET đọc, POST tạo, PUT cập nhật, DELETE xóa |
| **Stateless** | Mỗi request chứa đủ thông tin để xử lý | JWT token trong header |
| **Layered System** | Kiến trúc phân tầng rõ ràng | API Gateway → Controllers → Services → Repositories |
| **Uniform Interface** | Chuẩn hóa định dạng request/response | JSON với cấu trúc nhất quán |

### 1.2 HTTP Methods và Ý nghĩa

```http
GET     /api/v1/documents           - Lấy danh sách tài liệu (nhiều bản ghi)
GET     /api/v1/documents/{id}      - Lấy chi tiết một tài liệu
POST    /api/v1/documents           - Tạo mới tài liệu
PUT     /api/v1/documents/{id}      - Cập nhật toàn bộ tài liệu
PATCH   /api/v1/documents/{id}      - Cập nhật một phần tài liệu
DELETE  /api/v1/documents/{id}      - Xóa tài liệu (soft delete)
```

### 1.3 HTTP Status Codes

Hệ thống sử dụng các mã trạng thái HTTP chuẩn theo RFC 7231:

#### 2xx - Success
| Status Code | Ý nghĩa | Sử dụng |
|-------------|---------|---------|
| `200 OK` | Yêu cầu thành công | GET, PUT, PATCH thành công |
| `201 Created` | Tạo mới thành công | POST tạo resource mới |
| `202 Accepted` | Yêu cầu đã được chấp nhận | Async processing (upload file) |
| `204 No Content` | Thành công không có body | DELETE thành công |

#### 4xx - Client Errors
| Status Code | Ý nghĩa | Sử dụng |
|-------------|---------|---------|
| `400 Bad Request` | Request không hợp lệ | Validation failed |
| `401 Unauthorized` | Chưa xác thực | Thiếu hoặc token hết hạn |
| `403 Forbidden` | Không có quyền | Token hợp lệ nhưng không đủ quyền |
| `404 Not Found` | Resource không tồn tại | ID không tồn tại |
| `409 Conflict` | Xung đột dữ liệu | Trùng lặp dữ liệu |
| `422 Unprocessable Entity` | Dữ liệu không xử lý được | Validation rules violation |
| `429 Too Many Requests` | Quá nhiều requests | Rate limit exceeded |

#### 5xx - Server Errors
| Status Code | Ý nghĩa | Sử dụng |
|-------------|---------|---------|
| `500 Internal Server Error` | Lỗi server | Bug hoặc exception không xử lý |
| `502 Bad Gateway` | Gateway lỗi | Service downstream lỗi |
| `503 Service Unavailable` | Service không khả dụng | Maintenance hoặc overload |
| `504 Gateway Timeout` | Gateway timeout | Request downstream timeout |

### 1.4 Chiến lược Versioning

API versioning sử dụng URL path versioning với prefix `/api/v1/`:

```
/api/v1/documents
/api/v1/chat/sessions
/api/v1/auth/login
```

**Nguyên tắc versioning:**
- Version mới được release khi có breaking changes
- Version cũ được deprecated trước khi xóa (ít nhất 6 tháng)
- Response format có thể thay đổi trong cùng version (thêm fields)
- Breaking changes: đổi tên field, xóa field, đổi data type, đổi business rules

### 1.5 Quy ước Pagination

Hỗ trợ hai phương thức pagination:

**Offset-based Pagination (Default):**
```http
GET /api/v1/documents?page=1&page_size=20
```

**Cursor-based Pagination (cho dữ liệu lớn):**
```http
GET /api/v1/documents?cursor=eyJpZCI6MTIzfQ&limit=20
```

**Response pagination headers:**
```http
X-Total-Count: 150
X-Total-Pages: 8
X-Current-Page: 1
X-Page-Size: 20
X-Has-Next: true
X-Has-Prev: false
```

**Cấu trúc response với pagination:**
```json
{
  "data": [...],
  "pagination": {
    "page": 1,
    "page_size": 20,
    "total_items": 150,
    "total_pages": 8,
    "has_next": true,
    "has_prev": false
  }
}
```

## 2. Authentication APIs (`/api/v1/auth`)

Nhóm API xác thực và quản lý người dùng. Sử dụng JWT (JSON Web Token) với access token và refresh token mechanism.

### 2.1 POST `/api/v1/auth/register`

**Mô tả:** Đăng ký tài khoản người dùng mới trong hệ thống.

**Authorization:** None (Public endpoint)

**Request:**
```http
POST /api/v1/auth/register
Content-Type: application/json

{
  "email": "nguyen.van.a@example.com",
  "password": "SecurePass123!",
  "full_name": "Nguyễn Văn A",
  "department": "Kỹ thuật",
  "phone_number": "0912345678"
}
```

**Validation Rules:**

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| `email` | string | ✓ | Email format hợp lệ, unique trong hệ thống, max 255 ký tự |
| `password` | string | ✓ | Ít nhất 8 ký tự, 1 chữ hoa, 1 chữ thường, 1 số, 1 ký tự đặc biệt |
| `full_name` | string | ✓ | 2-100 ký tự, không chứa ký tự đặc biệt |
| `department` | string | ✗ | Max 100 ký tự, mặc định "General" |
| `phone_number` | string | ✗ | Format VN phone: 0xxxxxxxxx, 10-11 số |

**Success Response (201 Created):**
```json
{
  "success": true,
  "message": "Đăng ký thành công. Vui lòng kiểm tra email để xác thực tài khoản.",
  "data": {
    "user_id": "usr_a1b2c3d4e5f6",
    "email": "nguyen.van.a@example.com",
    "full_name": "Nguyễn Văn A",
    "department": "Kỹ thuật",
    "role": "user",
    "status": "pending_verification",
    "created_at": "2026-05-03T10:30:00Z"
  }
}
```

**Error Responses:**

*400 Bad Request - Validation Failed:*
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Dữ liệu đầu vào không hợp lệ",
    "details": [
      {"field": "email", "message": "Email đã được sử dụng trong hệ thống"},
      {"field": "password", "message": "Mật khẩu phải chứa ít nhất 1 ký tự đặc biệt"}

    "trace_id": "trc_7f8e9d0c1b2a3f4e"
  }

```

*409 Conflict - Email Existed:*
```json
{
  "error": {
    "code": "EMAIL_ALREADY_EXISTS",
    "message": "Email này đã được đăng ký trong hệ thống",
    "details": [],

    "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJ1c3JfYTFiMmMzZDRlNWY2IiwiaWQiOiJ0b2tlbl9jMzQ1Njc4OTgiLCJpYXQiOjE3MTAwMDAwMDAsImV4cCI6MTcxMDYzMTYwMH0.bC8dE0fG3hI5jK7lL9nP1qR4sT6uV8wX0yZ2aA5cD7e",
    "token_type": "Bearer",
    "expires_in": 3600,
    "refresh_expires_in": 604800
  }
}
```

**Token Refresh Flow:**
```
┌─────────┐                           ┌─────────┐
│  Client │                           │   API   │
└────┬────┘                           └────┬────┘
     │                                     │
     │  1. POST /auth/login                │
     │     {email, password}               │
     │ ─────────────────────────────────► │
     │                                     │
     │  2. Validate credentials             │
     │     Generate tokens                  │
     │ ◄───────────────────────────────── │
     │     {access_token, refresh_token}   │
     │                                     │
     │  3. API request with access_token   │
     │     (after 30-50 min)               │
     │ ─────────────────────────────────► │
     │                                     │
     │  4. Token expired (401)              │
     │ ◄───────────────────────────────── │
     │                                     │
     │  5. POST /auth/refresh               │
     │     {refresh_token}                 │
     │ ─────────────────────────────────► │
     │                                     │
     │  6. Validate refresh_token          │
     │     Rotate tokens                   │
     │ ◄───────────────────────────────── │
     │     {new_access_token,             │
     │      new_refresh_token}             │
     │                                     │
     │  7. Retry original request          │
     │ ─────────────────────────────────► │
     │                                     │
```

**Error Responses:**

*401 Unauthorized - Invalid/Expired Refresh Token:*
```json
{
  "error": {
    "code": "INVALID_REFRESH_TOKEN",
    "message": "Refresh token không hợp lệ hoặc đã hết hạn",
    "details": [],
    "trace_id": "trc_7f8e9d0c1b2a3f4e"
  }
}
```

## 3. Document APIs (`/api/v1/documents`)

Nhóm API quản lý tài liệu: upload, download, xem, cập nhật, và xóa.

### 3.1 POST `/api/v1/documents/upload`

**Mô tả:** Upload tài liệu mới lên hệ thống. Hỗ trợ multipart/form-data cho file và JSON metadata. Sau khi upload, file được xử lý async để trích xuất nội dung và tạo embeddings.

**Authorization:** Required (Bearer token)

**Request:**
```http
POST /api/v1/documents/upload
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Content-Type: multipart/form-data

------WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Disposition: form-data; name="file"; filename="bao-cao-nam-2026.pdf"
Content-Type: application/pdf

[data]
------WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Disposition: form-data; name="metadata"

{
  "title": "Báo cáo công tác năm 2026",
  "description": "Báo cáo tổng kết công tác năm 2026 của phòng Kỹ thuật",
  "category": "reports",
  "tags": ["báo cáo", "2026", "kỹ thuật"],
  "department": "Kỹ thuật",
  "is_public": true,
  "metadata": {
    "author": "Nguyễn Văn A",
    "document_date": "2026-01-15",
    "version": "1.0"
  }
}
------WebKitFormBoundary7MA4YWxkTrZu0gW--
```

**File Validation:**

| Property | Rules |
|----------|-------|
| Allowed Types | `.pdf`, `.docx`, `.doc`, `.txt`, `.md`, `.pptx`, `.xlsx`, `.csv` |
| Max File Size | 50MB |
| Max Files/Request | 5 files (batch upload) |
| Encoding | UTF-8 |

**Success Response (202 Accepted):**
```json
{
  "success": true,
  "message": "Tài liệu đang được xử lý. Bạn có thể kiểm tra trạng thái tại endpoint /documents/{id}/status",
  "data": {
    "document_id": "doc_x1y2z3a4b5c6",
    "filename": "bao-cao-nam-2026.pdf",
    "original_filename": "bao-cao-nam-2026.pdf",
    "file_size": 2456789,
    "mime_type": "application/pdf",
    "title": "Báo cáo công tác năm 2026",
    "status": "processing",
    "processing_status": {
      "current_step": "extracting_text",
      "progress_percentage": 15,
      "estimated_time_seconds": 45
    },
    "created_at": "2026-05-03T10:35:00Z"
  }
}
```

**Processing Status Flow:**
```
uploaded → queued → extracting_text → chunking → embedding → indexing → completed
                ↓
            failed (with error details)
```

### 3.2 GET `/api/v1/documents`

**Mô tả:** Lấy danh sách tài liệu với phân trang và bộ lọc.

**Authorization:** Required (Bearer token)

**Request:**
```http
GET /api/v1/documents?page=1&page_size=20&category=reports&department=Kỹ+thuật&status=completed&sort_by=created_at&sort_order=desc
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

**Query Parameters:**

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `page` | int | 1 | Số trang |
| `page_size` | int | 20 | Số items/trang (max: 100) |
| `category` | string | null | Lọc theo category |
| `department` | string | null | Lọc theo department |
| `status` | string | null | Trạng thái: `pending`, `processing`, `completed`, `failed` |
| `is_public` | bool | null | Lọc theo visibility |
| `search` | string | null | Tìm kiếm trong title/description |
| `date_from` | date | null | Lọc từ ngày (ISO 8601) |

## 11. API Security

### 11.1 JWT Authentication

**Token Structure:**
```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJ1c3JfYTFiMmMzZDRlNWY2Iiwicm9sZSI6InVzZXIiLCJpYXQiOjE3MTAwMDAwMDAsImV4cCI6MTcxMDAwMDM2MH0.s5Kx9L2mN8pQ3rT4uV6wX1yZ7aB0cD4eF8gH9jK2lM
```

**JWT Validation Rules:**
1. Verify signature với secret key
2. Check expiration (`exp` claim)
3. Check issuer (`iss` claim)
4. Check audience (`aud` claim)
5. Validate token type

### 11.2 CORS Configuration

```json
{
  "cors": {
    "allowed_origins": [
      "https://app.example.com",
      "https://admin.example.com"
    ],
    "allowed_methods": ["GET", "POST", "PUT", "DELETE", "PATCH"],
    "allowed_headers": [
      "Authorization",
      "Content-Type",
      "X-Request-ID",
      "X-Correlation-ID"
    ],
    "exposed_headers": [
      "X-RateLimit-Remaining",
      "X-RateLimit-Reset",
      "X-Total-Count"
    ],
    "max_age": 86400,
    "credentials": true
  }
}
```

### 11.3 Input Sanitization

**Rules:**
1. Strip HTML tags khỏi user inputs
2. Escape special characters trong queries
3. Validate file names (no path traversal)
4. Limit request body size
5. Sanitize search queries trước khi query database

**Example Sanitization:**
```
Input: "<script>alert('xss')</script>Hello World"
Output: "Hello World"

Input: "../../../etc/passwd"
Output: "_etc_passwd"

Input: "DROP TABLE users"
Output: "DROP TABLE users" (escaped in SQL)
```

### 11.4 Security Headers

```http
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
X-XSS-Protection: 1; mode=block
Strict-Transport-Security: max-age=31536000; includeSubDomains
Content-Security-Policy: default-src 'self'
Referrer-Policy: strict-origin-when-cross-origin
```

### B. HTTP Status Quick Reference

```
2xx - Success
  200 OK - Thành công
  201 Created - Đã tạo
  202 Accepted - Đã chấp nhận (async)
  204 No Content - Không có nội dung

4xx - Client Errors
  400 Bad Request - Request lỗi
  401 Unauthorized - Chưa đăng nhập
  403 Forbidden - Không có quyền
  404 Not Found - Không tìm thấy
  409 Conflict - Xung đột
  422 Unprocessable - Validation lỗi
  429 Too Many - Rate limit

5xx - Server Errors
  500 Internal Error - Lỗi server
  502 Bad Gateway - Gateway lỗi
  503 Unavailable - Service down
  504 Timeout - Gateway timeout
```
