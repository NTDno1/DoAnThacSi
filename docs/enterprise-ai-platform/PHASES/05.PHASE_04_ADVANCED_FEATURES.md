# Phase 4: Advanced Features

> **Mục tiêu**: Bổ sung các tính năng nâng cao: **Workflow Engine** (orchestration đa bước phức tạp với conditional, parallel, loop), **Voice Engine** (STT/TTS cho giao tiếp giọng nói), **SQL Engine** (Text-to-SQL cho phép hỏi đáp dữ liệu doanh nghiệp), **Memory Manager** (long-term memory cho Agent), **Hybrid Search + Reranker** (tăng độ chính xác retrieval), **Provider Cache** (cache LLM response), **Rate Limiter** (giới hạn tải), **External Connectors** (ERP, CRM, HRM, BI samples).
>
> **Demo cuối phase**: User dùng giọng nói hỏi "Doanh thu team Sales tháng 5?" → STT chuyển thành text → SQL Engine sinh SQL → chạy trên database → trả kết quả → TTS đọc kết quả. Workflow "Báo cáo tuần" tự động: query DB → RAG trên tài liệu → tạo dashboard → gửi email. Memory Agent nhớ được preferences và context qua nhiều session.

## 1. Tổng quan Phase 4

### 1.1 Tại sao là Phase 4 này?

Phase 3 đã có Agent framework hoàn chỉnh - AI có thể lập plan, gọi tool, xử lý task đa bước. Tuy nhiên, đó chỉ là **Agent reactive** (phản ứng theo từng request). Để trở thành platform enterprise thực sự, cần:

- **Workflow tự động** chạy theo lịch (VD: báo cáo tuần mỗi thứ 2).
- **Voice interface** cho UX tốt hơn (đặc biệt cho mobile, hands-free).
- **Truy vấn database doanh nghiệp** qua ngôn ngữ tự nhiên (Text-to-SQL).
- **Memory dài hạn** để Agent "nhớ" user qua nhiều session.
- **Retrieval chính xác hơn** (Hybrid Search + Reranker).
- **Tối ưu cost** qua caching, rate limiting.
- **Kết nối hệ thống doanh nghiệp** (ERP, CRM, HRM, BI).

### 1.2 Tóm tắt kỹ thuật

| Thành phần | Phase 3 → Phase 4 |
|------------|-------------------|
| Workflow Engine | Agent plan (single-run) → Workflow definitions reusable, scheduled, with DAG + conditionals + loops |
| Voice | Chưa có → STT (Whisper local / Deepgram) + TTS (ElevenLabs / OpenAI TTS) + WebRTC |
| SQL Engine | Chưa có → Text-to-SQL: schema retrieval, SQL gen, validation, execution, read-only DB user |
| Memory | Short-term (chat session) → Short-term + Long-term (vector store, importance scoring) |
| Hybrid Search | Vector only → Vector + BM25 + Reranker (cross-encoder) |
| Provider Cache | Chưa có → Exact match + Semantic cache với TTL |
| Rate Limiter | Chưa có → Multi-tier: global, tenant, user, endpoint, cost |
| External Connectors | Sample plugin → 8 connectors: ERP, DMS, CRM, HRM, Workflow, BI, Database, Document |
| Scheduled Jobs | Chưa có → Cron-based workflow trigger |
| Analytics Dashboard | Chưa có → Grafana dashboard + custom analytics page |

## 2. Phạm vi & Không phạm vi

### 2.1 Trong phạm vi (In Scope)

✅ **Workflow Engine**:
- `IWorkflowEngine` interface với: `StartAsync`, `GetAsync`, `ResumeAsync`, `CancelAsync`, `ScheduleAsync`.
- Workflow definition: DAG với step types `tool`, `agent`, `parallel`, `conditional`, `loop`, `human`, `wait`.
- Workflow definition stored trong DB (JSON), có thể edit qua UI.
- Workflow instance: runtime state, persist sau mỗi step.
- Scheduled trigger: cron expression (VD: "0 9 * * 1" = mỗi thứ 2 9h sáng).
- Webhook trigger: gọi từ external system.
- Manual trigger: từ UI/API.
- Reusable workflow: 1 definition chạy nhiều lần với input khác nhau.
- Per-tenant workflow library.

✅ **Voice Engine**:
- `IVoiceEngine` interface: `SpeechToTextAsync`, `TextToSpeechAsync` (streaming).
- STT providers: Whisper (local, free), Deepgram (cloud, fast).
- TTS providers: ElevenLabs (best quality), OpenAI TTS, Edge TTS (free).
- Auto-detect language (Vietnamese, English).
- WebRTC cho low-latency audio streaming.
- VAD (Voice Activity Detection) để lọc silence.
- Audio format: PCM, WAV, MP3, Opus, WebM.
- Phase 4: synchronous STT/TTS qua REST API. Realtime WebRTC sẽ làm ở phase sau (nếu cần).

✅ **SQL Engine (Text-to-SQL)**:
- `ISQLEngine` interface: `QueryAsync(question, dbContext)`.
- Pipeline: question → schema retrieval (tìm relevant tables) → SQL generation (LLM) → SQL validation (parser + safety) → execution → result → NL answer.
- Schema retrieval: embed tên table + column → vector search → top relevant tables.
- SQL generation: prompt LLM với schema + question → SQL.
- SQL validation: 
  - Chỉ cho phép SELECT (cấm INSERT, UPDATE, DELETE, DROP, ALTER).
  - Bắt buộc có LIMIT (mặc định 1000).
  - Parse AST (dùng SqlParser) để check.
- Execution: dùng read-only DB user.
- Result format: rows + NL answer + optional chart suggestion.
- Security: row-level security theo tenant, whitelist tables.

✅ **Memory Manager**:
- Short-term memory: trong Redis, TTL = 24h, lưu recent messages + context.
- Long-term memory: trong Vector Store, lưu facts, preferences, summaries.
- Auto-extract memory-worthy info từ conversation (LLM-based + rule-based).
- Importance scoring (0-1) cho mỗi memory.
- Memory retrieval: embed query → tìm top-k relevant memories → thêm vào context.
- Memory consolidation: gộp các memory liên quan, xóa memory cũ ít quan trọng.
- User preferences: lưu riêng (model preference, language, etc.).

✅ **Hybrid Search + Reranker**:
- Vector search (giữ nguyên Phase 2).
- BM25 (PostgreSQL full-text search).
- Hybrid: RRF (Reciprocal Rank Fusion) kết hợp 2 score.
- Reranker: Cohere Rerank (cloud) hoặc BGE-reranker (local).
- Config: vectorWeight, keywordWeight, topK (pre-rerank), topN (post-rerank).
- Per-tenant config.

✅ **Provider Cache**:
- Exact match cache: key = hash(prompt + model + temperature + params).
- Semantic cache: key = embedding của prompt, threshold similarity = 0.95.
- TTL: 24h exact, 1h semantic (configurable).
- Storage: Redis (exact) + pgvector (semantic).
- Per-tenant namespace.
- Invalidation: theo tenant, theo provider, manual.

✅ **Rate Limiter**:
- Multi-tier:
  - L1 Global: tổng platform.
  - L2 Tenant: per tenant.
  - L3 User: per user.
  - L4 Endpoint: per endpoint.
  - L5 Cost: per tenant (token spend).
- Algorithm: token bucket + sliding window.
- Storage: Redis + Lua script (atomic).
- Config: per-tenant, per-tier.
- Response: HTTP 429 + Retry-After header + RateLimit-* headers.
- Metrics: emit rate_limit_exceeded counter.

✅ **External Connectors (8 loại)**:
- **ERP Connector**: sample cho Odoo (REST API) - tools: search_sales_orders, get_customer, get_inventory.
- **DMS Connector**: sample cho Nextcloud - tools: search_documents, get_document, upload_document.
- **CRM Connector**: sample cho HubSpot - tools: search_customers, get_opportunity, create_lead.
- **HRM Connector**: sample cho BambooHR - tools: get_employee, create_leave_request, get_payslip.
- **Workflow Connector**: sample cho n8n - tools: start_workflow, get_workflow_status.
- **BI Connector**: sample cho Metabase - tools: get_dashboard, get_question.
- **Database Connector**: generic - tools: execute_sql (read-only).
- **Document Connector**: Google Drive / S3 - tools: search_files, get_file_content.

Mỗi connector có:
- Configuration class (endpoint, auth).
- Service class implement IConnector.
- Tools exposed to ToolRegistry.
- Health check.
- Unit + integration test.

✅ **Scheduler**:
- Cron-based: Quartz.NET hoặc custom implementation.
- Workflow trigger: mỗi cron tick → tìm workflows cần chạy → start instance.
- Per-tenant schedule: mỗi tenant có thể set schedule riêng.
- Schedule history: lưu các lần chạy.

✅ **Analytics Dashboard**:
- Backend API: `/api/v1/analytics/usage`, `/api/v1/analytics/cost`, `/api/v1/analytics/performance`.
- Frontend: trang `/analytics` với chart (Recharts).
- Metrics:
  - LLM usage: tokens, cost, by provider/model.
  - RAG usage: queries, retrieval score, citation rate.
  - Agent usage: runs, success rate, step duration.
  - Tool usage: calls, success rate, by tool.
  - User activity: active users, top queries.

✅ **API mới**:
- Workflow: CRUD, trigger, list instances.
- Voice: STT, TTS, list voices.
- SQL: query, list database connections.
- Memory: list, search, delete.
- Analytics: usage, cost, performance.
- Connectors: list, test, configure.
- Cache: stats, invalidate.
- Rate limit: status, config.

✅ **Frontend mở rộng**:
- Trang `/workflows`: list, designer (drag-drop), instances.
- Trang `/voice`: voice chat UI (record, transcribe, send).
- Trang `/analytics`: dashboard với chart.
- Trang `/connectors`: list, configure, test.
- Trang `/memory`: list memories, search, delete.
- Workflow designer: dùng ReactFlow.

✅ **Tests mở rộng**:
- Unit test: WorkflowEngine, VoiceEngine, SQLEngine, MemoryManager, HybridSearch, RateLimiter, các connector.
- Integration test: workflow scheduled trigger, voice round-trip, SQL end-to-end, memory retrieval.
- E2E: voice chat → SQL query → TTS response.

```csharp
public interface IWorkflowEngine
{
    Task<WorkflowInstance> StartAsync(WorkflowStartRequest request, CancellationToken ct);
    Task<WorkflowInstance?> GetAsync(Guid instanceId, CancellationToken ct);
    Task ResumeAsync(Guid instanceId, WorkflowResumeRequest request, CancellationToken ct);

    Task<Guid> ScheduleAsync(WorkflowScheduleRequest request, CancellationToken ct);
    Task UnscheduleAsync(Guid scheduleId, CancellationToken ct);
}

public record WorkflowDefinition(
    Guid Id,
    string Name,
    string? Description,
    int Version,
    IReadOnlyList<WorkflowStep> Steps,
    WorkflowTrigger? Trigger,
    Guid TenantId,

    string Id,                              // unique trong workflow
    string Name,
    StepType Type,
    string? ToolName,

    int? MaxIterations,                     // cho loop
    bool RequiresApproval,
    int? TimeoutSeconds

public record WorkflowInstance(
```

## 3. Acceptance Criteria

Phase 4 hoàn thành khi **TẤT CẢ** các tiêu chí sau đạt:

### 3.1 Build & Runtime

- [ ] `dotnet build` thành công, không có warning.
- [ ] `docker compose up` chạy được, Phase 1+2+3 vẫn hoạt động.
- [ ] Redis cache hoạt động (test set/get).
- [ ] Cron scheduler chạy (test workflow tự động trigger).

### 3.2 Functional - Workflow Engine

- [ ] Tạo workflow definition qua API hoặc UI (DAG với 5+ steps).
- [ ] Start workflow instance thành công.
- [ ] Steps thuộc nhóm parallel chạy đồng thời.
- [ ] Conditional step chỉ chạy khi condition true.
- [ ] Loop step chạy đúng số lần (test với 3 iterations).
- [ ] Workflow pause khi gặp step `human`, resume khi có approval.
- [ ] Workflow instance có thể cancel.
- [ ] Workflow variables được share giữa các steps.
- [ ] Workflow tự động trigger theo cron (test với cron "*/1 * * * *" chạy mỗi phút).
- [ ] Workflow definition reusable: chạy nhiều instance với input khác nhau.

### 3.3 Functional - Voice Engine

- [ ] Upload audio file (.wav, .mp3) → STT trả về text.
- [ ] Test với audio Tiếng Việt: "Xin chào" → "Xin chào".
- [ ] Test với audio Tiếng Anh: "Hello" → "Hello".
- [ ] Text → TTS trả về audio file (mp3/wav).
- [ ] List voices available cho mỗi provider.
- [ ] Whisper local hoạt động (free, offline).
- [ ] OpenAI TTS hoạt động (cần API key).
- [ ] Frontend có thể record audio từ microphone, gửi lên backend, nhận transcription.

### 3.4 Functional - SQL Engine

- [ ] Cấu hình database connection (PostgreSQL) với read-only user.
- [ ] Schema được auto-discover khi tạo connection.
- [ ] Hỏi "Có bao nhiêu user?" → sinh SQL `SELECT COUNT(*) FROM users` → execute → trả kết quả.
- [ ] Hỏi "Doanh thu tháng 5 của team Sales?" → sinh SQL với JOIN, WHERE, GROUP BY → execute → trả NL answer.
- [ ] SQL chỉ SELECT, có LIMIT (verified).
- [ ] SQL có INSERT/UPDATE/DELETE bị reject với lỗi rõ ràng.
- [ ] Câu hỏi ngoài phạm vi (table không tồn tại) → trả lỗi rõ ràng.
- [ ] Chart suggestion cho query có aggregate.

### 3.5 Functional - Memory Manager

- [ ] Chat session A, user nói "Tôi thích dùng OpenAI" → memory lưu preference.
- [ ] Chat session B (khác session), user hỏi câu liên quan → memory được retrieve, thêm vào context.
- [ ] LLM tự trích memory-worthy info (preferences, facts).
- [ ] Memory có importance score, search ranking theo importance + recency.
- [ ] User có thể list, search, delete memory qua UI.
- [ ] Long-term memory persist qua nhiều session.

### 3.6 Functional - Hybrid Search + Reranker

- [ ] Hybrid search kết hợp vector + BM25 với RRF.
- [ ] Reranker cải thiện ranking (so sánh trước/sau rerank).
- [ ] Config được per-tenant: vectorWeight, keywordWeight, topK, topN.
- [ ] Search với metadata filter (e.g. `metadata.department = 'HR'`) hoạt động.

### 3.7 Functional - Provider Cache

- [ ] Repeat query với cùng prompt → cache hit, không gọi LLM.
- [ ] Similar query (semantic) với threshold 0.95 → cache hit.
- [ ] Cache miss với prompt khác → gọi LLM, lưu cache.
- [ ] TTL expire → cache miss.
- [ ] Per-tenant cache isolation (không leak giữa tenant).
- [ ] Cache stats API trả về hit rate, size.

### 3.8 Functional - Rate Limiter

- [ ] User gửi 100 request/phút → 70 thành công, 30 bị 429.
- [ ] Response có Retry-After header.
- [ ] Tenant quota: tổng token spend vượt → 429.
- [ ] Endpoint-specific: `/api/v1/agent/run` rate limit 10/giờ.
- [ ] Rate limit metrics được emit.

### 3.9 Functional - External Connectors

- [ ] Có 8 connectors: ERP, DMS, CRM, HRM, Workflow, BI, Database, Document.
- [ ] Mỗi connector có config UI, test connection, enable/disable.
- [ ] Sample tool hoạt động: vd `connector_hubspot.search_customers`.
- [ ] Database connector: list tables, execute SELECT, có row limit.

### 4.3 Luồng Workflow Scheduled

```
1. Admin define workflow "Weekly Report" trong UI:
   - Trigger: cron "0 9 * * 1" (mỗi thứ 2 9h)
   - Steps:
     a. query_db (tool): "SELECT * FROM sales WHERE week = :last_week"
     b. summarize (agent): "Tóm tắt báo cáo tuần: {{steps.a.output}}"
     c. send_email (tool): "Gửi email cho manager với nội dung: {{steps.b.output}}"
   - Save WorkflowDefinition (JSON)

2. SchedulerService khởi động:
   - Load tất cả workflow có trigger.cron
   - Quartz.NET: lập lịch trigger cho mỗi workflow

3. Đến thời điểm (thứ 2 9h):
   - Quartz fire WorkflowJob
   - Tạo WorkflowInstance (status: pending → running)
   - Step a: query_db → execute → output = rows
   - Step b: summarize → agent với context → output = summary
   - Step c: send_email → execute → output = sent
   - Status: completed
   - Emit event WorkflowCompleted

4. Admin xem workflow instances trong UI:
   - List instances, filter theo status
   - Drill-down: xem từng step execution, duration, output, error
```

### 4.4 Luồng Voice Chat

```
1. User mở /chat, click button voice
2. Frontend xin quyền microphone
3. User nói: "Xin chào, hôm nay thời tiết thế nào?"
4. Frontend record audio (WebM/Opus)
5. POST /api/v1/voice/stt với audio
6. Backend VoiceEngine.SpeechToTextAsync:
   - WhisperSttProvider gọi Ollama (hoặc local whisper.cpp)
   - Trả về "Xin chào, hôm nay thời tiết thế nào?"
7. Frontend nhận text, hiển thị trong input
8. User bấm Enter hoặc tự động gửi:
   - Chat như bình thường (RAG/Agent)
9. Backend trả response text
10. Frontend gọi POST /api/v1/voice/tts với response text
11. Backend VoiceEngine.TextToSpeechAsync:
    - OpenAITtsProvider gọi OpenAI TTS
    - Trả về audio stream (MP3)
12. Frontend play audio qua <audio> element
13. User nghe response
```

### 4.5 Luồng SQL Engine

```
1. User hỏi: "Có bao nhiêu khách hàng VIP mua hàng trong tháng 5?"
2. Backend SQLEngine.QueryAsync:
   a. Schema Retrieval:
      - Embed câu hỏi
      - Tìm relevant tables: customers, orders, ...
      - Trả schema context
   b. SQL Generation:
      - Prompt LLM: "Given schema [customers, orders], generate SQL for: 'Có bao nhiêu khách hàng VIP mua hàng trong tháng 5?'"
      - LLM sinh: SELECT COUNT(DISTINCT c.id) FROM customers c JOIN orders o ON c.id = o.customer_id WHERE c.tier = 'VIP' AND o.created_at BETWEEN '2026-05-01' AND '2026-05-31'
   c. SQL Validation:
      - Parse AST
      - Check: chỉ SELECT ✓
      - Check: có LIMIT (thêm nếu thiếu) → SELECT ... LIMIT 1000
      - Check: tables đều trong whitelist ✓
   d. Execution:
      - Connect tới read-only DB user
      - Execute SQL
      - Trả rows: [{count: 42}]
   e. Result Formatting:
      - LLM tóm tắt: "Có 42 khách hàng VIP đã mua hàng trong tháng 5."
   f. Chart Suggestion:
      - Phát hiện có aggregate → suggest bar chart hoặc stat card
3. Return SQLResult {
   sql, answer, rows, chartSuggestion, metrics
}
```

## 7. Data Model mở rộng

### 7.1 Bảng mới (10 bảng)

```sql
-- Bảng workflow_definitions: reusable workflow
CREATE TABLE workflow_definitions (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    name            VARCHAR(200) NOT NULL,
    description     TEXT,
    version         INT NOT NULL DEFAULT 1,
    definition_json JSONB NOT NULL,        -- steps, trigger, variables
    is_active       BOOLEAN NOT NULL DEFAULT true,
    created_by      UUID REFERENCES users(id),
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Bảng workflow_instances: runtime state
CREATE TABLE workflow_instances (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    definition_id   UUID NOT NULL REFERENCES workflow_definitions(id),
    user_id         UUID REFERENCES users(id),
    status          VARCHAR(20) NOT NULL DEFAULT 'pending',
    variables_json  JSONB,
    current_step    VARCHAR(100),
    error_message   TEXT,
    started_at      TIMESTAMPTZ,
    completed_at    TIMESTAMPTZ,
    triggered_by    VARCHAR(50),           -- 'manual' | 'cron' | 'webhook' | 'api'
    metadata        JSONB,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Bảng workflow_step_executions
CREATE TABLE workflow_step_executions (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    instance_id     UUID NOT NULL REFERENCES workflow_instances(id) ON DELETE CASCADE,
    step_id         VARCHAR(100) NOT NULL,
    status          VARCHAR(20) NOT NULL,
    input_json      JSONB,
    output_json     JSONB,
    error_message   TEXT,
    started_at      TIMESTAMPTZ,
    completed_at    TIMESTAMPTZ,
    duration_ms     INT,
    attempt_count   INT NOT NULL DEFAULT 0
);

-- Bảng workflow_schedules: cron schedules
CREATE TABLE workflow_schedules (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    definition_id   UUID NOT NULL REFERENCES workflow_definitions(id) ON DELETE CASCADE,
    cron_expression VARCHAR(100) NOT NULL,
    is_enabled      BOOLEAN NOT NULL DEFAULT true,
    last_run_at     TIMESTAMPTZ,
    next_run_at     TIMESTAMPTZ,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Bảng user_memories: long-term memory
CREATE TABLE user_memories (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    user_id         UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    type            VARCHAR(50) NOT NULL,           -- 'preference' | 'fact' | 'summary' | 'context'
    content         TEXT NOT NULL,
    embedding       VECTOR(768),                    -- pgvector
    importance      DOUBLE PRECISION NOT NULL DEFAULT 0.5,
    source_session  UUID REFERENCES chat_sessions(id) ON DELETE SET NULL,
    last_accessed   TIMESTAMPTZ,
    access_count    INT NOT NULL DEFAULT 0,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_user_memories_user ON user_memories(user_id, importance DESC, last_accessed DESC);
CREATE INDEX idx_user_memories_embedding ON user_memories USING ivfflat (embedding vector_cosine_ops);

-- Bảng database_connections: cho SQL Engine
CREATE TABLE database_connections (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    name            VARCHAR(200) NOT NULL,
    driver          VARCHAR(50) NOT NULL,           -- 'postgresql' | 'mysql' | 'mssql'
    host            VARCHAR(500) NOT NULL,
    port            INT NOT NULL,
    database        VARCHAR(200) NOT NULL,
    username        VARCHAR(200) NOT NULL,
    password_secret_ref VARCHAR(500) NOT NULL,      -- ref to secret manager
    is_readonly     BOOLEAN NOT NULL DEFAULT true,
    allowed_tables  TEXT[],
    schema_cache    JSONB,                          -- cached schema
    schema_cached_at TIMESTAMPTZ,
    is_enabled      BOOLEAN NOT NULL DEFAULT true,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Bảng voice_sessions
CREATE TABLE voice_sessions (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    user_id         UUID NOT NULL REFERENCES users(id),
    session_id      UUID REFERENCES chat_sessions(id) ON DELETE SET NULL,
    stt_provider    VARCHAR(50),
    tts_provider    VARCHAR(50),
    language        VARCHAR(10),
    duration_ms     INT,
    transcript      TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Bảng connectors
CREATE TABLE connectors (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    name            VARCHAR(200) NOT NULL,
    type            VARCHAR(50) NOT NULL,            -- 'erp' | 'dms' | 'crm' | ...
    config          JSONB,                          -- connection details (encrypted)
    secrets_ref     VARCHAR(500),                   -- ref to secret manager
    is_enabled      BOOLEAN NOT NULL DEFAULT true,
    is_healthy      BOOLEAN,
    last_health_check TIMESTAMPTZ,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Bảng analytics_events
CREATE TABLE analytics_events (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    user_id         UUID REFERENCES users(id),
    event_type      VARCHAR(100) NOT NULL,          -- 'llm_call' | 'rag_query' | 'agent_run' | 'tool_call' | 'voice_stt' | 'voice_tts' | 'sql_query'
    event_data      JSONB NOT NULL,
    cost_usd        DECIMAL(10, 6),
    tokens_total    INT,
    duration_ms     INT,
    occurred_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_analytics_tenant_time ON analytics_events(tenant_id, occurred_at DESC);
CREATE INDEX idx_analytics_event_type ON analytics_events(event_type, occurred_at DESC);
CREATE INDEX idx_analytics_user ON analytics_events(user_id, occurred_at DESC);

-- Bảng rate_limit_configs
CREATE TABLE rate_limit_configs (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID,                            -- NULL = global
    scope           VARCHAR(50) NOT NULL,            -- 'global' | 'tenant' | 'user' | 'endpoint' | 'cost'
    identifier      VARCHAR(200),                    -- specific path, userId, etc.
    limit_value     INT NOT NULL,
    window_seconds  INT NOT NULL,
    is_enabled      BOOLEAN NOT NULL DEFAULT true,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### 9.1 Luồng Workflow Scheduled (Weekly Report)

```
1. Admin mở /workflows/new
2. Kéo thả steps:
   - Step 1: "Query Sales" (tool) → tool: execute_sql
   - Step 2: "Summarize" (agent) → prompt template
   - Step 3: "Send Email" (tool) → tool: send_email
3. Kết nối: Step 1 → Step 2 → Step 3
4. Set trigger: cron "0 9 * * 1" (mỗi thứ 2 9h)
5. Save workflow

6. QuartzScheduler lập lịch
7. Thứ 2 9h: trigger fire
8. WorkflowEngine.StartAsync:
   - Tạo instance
   - Step 1: query sales → rows
   - Step 2: summarize với context → text
   - Step 3: send email → sent
9. Status: completed
10. Admin xem trong /workflows/{id}/instances
```

## Phụ lục A: Common Pitfalls

### A.1 Whisper OOM với audio dài

**Vấn đề**: Whisper local load cả file audio vào memory, file 1 giờ có thể OOM.

**Giải pháp**: Chia audio thành chunk 30s, transcribe từng chunk.

### A.2 SQL injection qua LLM-generated SQL

**Vấn đề**: LLM có thể sinh SQL có chuỗi nguy hiểm.

**Giải pháp**: 
- Chỉ dùng parameterized query.
- Validate với parser AST (không chỉ regex).
- Reject nếu có chuỗi lạ.

### A.3 Cron job chạy trùng lặp

**Vấn đề**: Nếu 1 instance workflow trigger mất 2 phút, cron 1 phút sẽ tạo 2 instance.

**Giải pháp**: Quartz hỗ trợ `DisallowConcurrentExecution` để chỉ chạy 1 job tại 1 thời điểm.

### A.4 Memory quá nhiều → context quá dài

**Vấn đề**: User có 1000 memories, retrieve top-10, thêm vào context → context > LLM limit.

**Giải pháp**: 
- Cap số memory tối đa: top 5.
- Filter theo importance ≥ 0.6.
- Summarize old memories.

### A.5 Rate limit check fail-open

**Vấn đề**: Redis down → rate limiter không check → request đi qua → DDoS.

**Giải pháp**: Fail-closed khi Redis down: trả 503. Hoặc fail-open với cảnh báo (tùy use case).

### A.6 Audio format không support

**Vấn đề**: User upload audio format không support.

**Giải pháp**: 
- Validate format ở frontend.
- Backend: convert sang format support (FFmpeg).
- Trả lỗi rõ ràng nếu không convert được.
