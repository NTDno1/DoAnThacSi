> **Demo cuối phase**: Upload PDF tài liệu → hệ thống tự động parse, chunk, embed → user hỏi đáp dựa trên nội dung PDF, có citation trích nguồn. Có thể chuyển đổi qua lại giữa Ollama (local) và OpenAI (cloud).

## 1. Tổng quan Phase 2

### 1.1 Tại sao là Phase 2 này?

Phase 1 đã có **Walking Skeleton**: chat với LLM, lưu lịch sử, có auth. Nhưng platform lúc này chỉ là "chatbot" thuần, chưa có khả năng **truy xuất tri thức** (RAG) - tức là chưa thể trả lời câu hỏi dựa trên tài liệu riêng của doanh nghiệp.

Phase 2 bổ sung **AI Engine Core** - khả năng quan trọng nhất của platform:
- Nhúng tài liệu (document ingestion).
- Tìm kiếm ngữ nghĩa (semantic search).
- Tạo câu trả lời có trích dẫn (RAG with citation).
- Hỗ trợ **multi-provider** (chuyển đổi giữa Ollama local và OpenAI cloud).
- **Tool Engine cơ bản** để LLM có thể gọi hàm (VD: gọi API thời tiết, tính toán).

### 1.2 Tóm tắt kỹ thuật

| Thành phần | Phase 1 → Phase 2 |
|------------|-------------------|
| Embedding | Chưa có → Ollama Embedding (nomic-embed-text) + OpenAI Embedding (text-embedding-3-small) |
| Vector Store | Chưa có → pgvector (PostgreSQL extension) với abstraction IVectorStore |
| RAG Engine | Chưa có → RAG pipeline: query → embed → search → rerank → prompt → LLM → citation |
| Document Ingestion | Chưa có → upload PDF/TXT/MD/DOCX → parse → chunk → embed → index |
| Tool Engine | Chưa có → IToolRegistry + built-in tools (calculator, web_search, current_time) |
| Provider Router | Chỉ Ollama → Multi-provider với chiến lược chọn (cost, latency, fallback) |
| Provider mới | - → OpenAI (GPT-4o-mini, GPT-4o) + Embedding |
| Document Parser | - → iText7 (PDF), Open XML (DOCX), Markdig (MD) |
| Background Job | - → Hangfire hoặc custom BackgroundService cho document indexing |
| API mới | - | `/api/v1/documents/*`, `/api/v1/rag/*`, `/api/v1/tools/*` |
| Frontend | Chat đơn giản → Chat + Document manager + RAG toggle |

## 2. Phạm vi & Không phạm vi

### 2.1 Trong phạm vi (In Scope)

✅ **Embedding Provider**:
- `IEmbeddingProvider` interface với `EmbedAsync` và `BatchEmbedAsync`.
- `OllamaEmbeddingProvider` (model: `nomic-embed-text`, 768 dims).
- `OpenAIEmbeddingProvider` (model: `text-embedding-3-small`, 1536 dims).
- `IEmbeddingProviderFactory` chọn provider theo config.

✅ **Vector Store**:
- `IVectorStore` interface với: `UpsertAsync`, `SearchAsync`, `DeleteAsync`, `CreateCollectionAsync`.
- `PgVectorStore` implementation (dùng Npgsql + pgvector).
- Hỗ trợ: cosine distance, IVFFlat index, batch insert, metadata filter.
- `IVectorStoreFactory` để swap implementation sau này (Qdrant, Milvus).

✅ **Document Ingestion**:
- `IDocumentParser` interface.
- Parsers: `PdfDocumentParser` (iText7), `DocxDocumentParser` (Open XML SDK), `TxtDocumentParser`, `MarkdownDocumentParser` (Markdig).
- Auto-detect MIME type.
- Streaming upload (không load toàn bộ file vào memory).

✅ **Chunking**:
- `IChunker` interface.
- `FixedSizeChunker` (chunk theo token count, có overlap).
- `RecursiveChunker` (chia theo paragraph, sentence).
- `MarkdownChunker` (chia theo heading/section).
- Config: chunk_size, chunk_overlap.

✅ **RAG Engine**:
- `IRAGEngine` interface: `QueryAsync`, `StreamQueryAsync`.
- Pipeline: Query → embed → retrieve (top-k) → context build → LLM → citation extract.
- Support 2 strategy đơn giản: `Vector`, `Vector+BM25` (hybrid cơ bản).
- Citation: chỉ ra document nào, chunk nào, text snippet.
- Streaming response.

✅ **Tool Engine (cơ bản)**:
- `ITool` interface.
- `IToolRegistry` quản lý tools.
- Built-in tools: `CalculatorTool`, `CurrentTimeTool`, `WebSearchTool` (mock hoặc DuckDuckGo thật).
- `ToolCall` tracking (ai gọi, lúc nào, kết quả).
- Phase 2 chỉ làm **synchronous tool**, không có async long-running.

✅ **Provider Router (mở rộng)**:
- Hỗ trợ multi-provider config: Ollama + OpenAI.
- Selection strategies: `CheapestFirst`, `FastestFirst`, `Fallback` chain, `TenantPinned`.
- Health check provider mỗi 30s.
- Auto-failover khi provider chính down.
- Track cost, latency, error rate per provider.

✅ **OpenAI Provider**:
- `OpenAIProvider` implement `ILLMProvider`.
- `OpenAIEmbeddingProvider` implement `IEmbeddingProvider`.
- Models: `gpt-4o-mini`, `gpt-4o`, `text-embedding-3-small`.
- Hỗ trợ streaming, retry, circuit breaker.

✅ **Background Job cho Document Indexing**:
- Dùng `IHostedService` đơn giản (không cần Hangfire cho Phase 2).
- Queue document IDs cần index, worker xử lý tuần tự.
- Update status: pending → processing → ready/failed.
- Retry với exponential backoff.

✅ **API mới**:
- `POST /api/v1/documents` - upload document.
- `GET /api/v1/documents` - list documents.
- `GET /api/v1/documents/{id}` - chi tiết document.
- `DELETE /api/v1/documents/{id}` - xóa document.
- `GET /api/v1/documents/{id}/chunks` - xem chunks (debug).
- `POST /api/v1/rag/query` - RAG query (non-streaming).
- `POST /api/v1/rag/query/stream` - RAG streaming.
- `GET /api/v1/tools` - list tools có sẵn.
- `POST /api/v1/tools/{name}/call` - gọi tool trực tiếp (test).

✅ **Frontend mở rộng**:
- Sidebar mới: thêm "Documents" link.
- Trang `/documents`: upload, list, delete, xem status indexing.
- Trang `/chat`: thêm toggle "Use RAG" + chọn collection.
- Citation rendering: hiển thị `[1]`, `[2]` dưới message, click mở modal xem source.
- File upload drag-drop.

✅ **Tests mở rộng**:
- Unit test: PgVectorStore (với Testcontainers), RAGEngine, Chunkers, Parsers, ToolRegistry, ProviderRouter, OpenAIProvider.
- Integration test: upload PDF → đợi indexed → RAG query có citation.
- E2E test: upload → chat với RAG.

❌ Reranker model (cross-encoder) - chỉ dùng vector score.

❌ Auto-update document (khi file thay đổi).

❌ Agent (planning, tool orchestration phức tạp) - chỉ single tool call.

❌ SQL Engine.
❌ Workflow.

### 2.3 Interface mới được chốt ở Phase 2

```csharp
// IEmbeddingProvider
public interface IEmbeddingProvider
{
    string ProviderId { get; }
    int Dimensions { get; }
    Task<EmbedResponse> EmbedAsync(EmbedRequest request, CancellationToken ct);
    Task<IReadOnlyList<EmbedResponse>> BatchEmbedAsync(BatchEmbedRequest request, CancellationToken ct);
    ProviderHealth HealthCheckAsync(CancellationToken ct);
}

public record EmbedRequest(
    string ModelId,
    string Text,
    Guid? TenantId = null
);

public record BatchEmbedRequest(
    string ModelId,
    IReadOnlyList<string> Texts,
    Guid? TenantId = null
);

public record EmbedResponse(
    float[] Vector,
    string ModelId,
    int TokensUsed,
    TimeSpan Latency
);

// IVectorStore
public interface IVectorStore
{
    Task UpsertAsync(VectorCollection collection, IReadOnlyList<VectorRecord> records, CancellationToken ct);
    Task<IReadOnlyList<VectorSearchResult>> SearchAsync(VectorSearchRequest request, CancellationToken ct);
    Task DeleteAsync(VectorCollection collection, IReadOnlyList<Guid> ids, CancellationToken ct);
    Task CreateCollectionAsync(VectorCollection collection, CancellationToken ct);
    Task DeleteCollectionAsync(VectorCollection collection, CancellationToken ct);
}

public record VectorCollection(
    Guid Id,
    string Name,
    int Dimensions,
    string DistanceMetric,    // "cosine" | "euclidean" | "dot_product"
    Guid TenantId
);

public record VectorRecord(
    Guid Id,
    float[] Vector,
    string Content,
    IReadOnlyDictionary<string, object>? Metadata
);

public record VectorSearchRequest(
    VectorCollection Collection,
    float[] QueryVector,
    int TopK = 10,
    double MinScore = 0.0,
    IReadOnlyDictionary<string, object>? Filters = null,
    bool IncludeContent = true
);

public record VectorSearchResult(
    Guid Id,
    float Score,
    string Content,
    IReadOnlyDictionary<string, object>? Metadata
);

// IRAGEngine
public interface IRAGEngine
{
    Task<RAGResponse> QueryAsync(RAGQuery query, CancellationToken ct);
    IAsyncEnumerable<RAGStreamChunk> StreamQueryAsync(RAGQuery query, CancellationToken ct);
}

public record RAGQuery(
    string Query,
    Guid TenantId,
    Guid? CollectionId = null,
    Guid? UserId = null,
    Guid? SessionId = null,
    int TopK = 5,
    RAGStrategy Strategy = RAGStrategy.Vector,
    ChatRequestOptions? Options = null
);

public enum RAGStrategy { Vector, Hybrid }

public record RAGResponse(
    string Answer,
    IReadOnlyList<Citation> Citations,
    RAGMetrics Metrics
);

public record RAGStreamChunk(
    string? ContentDelta,
    string? FinishReason,
    CitationAccumulator? Citations,
    RAGMetrics? Metrics
);

public record Citation(
    int Index,
    Guid DocumentId,
    Guid ChunkId,
    string DocumentTitle,
    string TextSnippet,
    int? PageNumber,
    double RelevanceScore
);

public record RAGMetrics(
    int RetrievalLatencyMs,
    int LlmLatencyMs,
    int TotalLatencyMs,
    int PromptTokens,
    int CompletionTokens,
    int TotalTokens,
    int RetrievedChunks,
    string Model
);

// ITool
public interface ITool
{
    string Name { get; }
    string Description { get; }
    ToolParameterSchema Parameters { get; }
    Task<ToolResult> ExecuteAsync(string argumentsJson, ToolExecutionContext context, CancellationToken ct);
}

public record ToolExecutionContext(
    Guid TenantId,
    Guid UserId,
    Guid? SessionId,
    string? TraceId
);

public record ToolResult(
    bool Success,
    string OutputJson,
    string? ErrorMessage = null
);

public record ToolParameterSchema(
    string Type,        // "object"
    Dictionary<string, ToolParameterProperty> Properties,
    string[] Required
);

public record ToolParameterProperty(
    string Type,
    string Description,
    object? Default = null,
    string[]? Enum = null
);

// IToolRegistry
public interface IToolRegistry
{
    void Register(ITool tool);
    void Unregister(string toolName);
    ITool? Get(string toolName);
    IReadOnlyList<ITool> ListAll(Guid tenantId);
    Task<ToolResult> ExecuteAsync(string toolName, string argumentsJson, ToolExecutionContext ctx, CancellationToken ct);
}
```

**Lưu ý**: Tất cả interface trên sẽ được sử dụng trong Phase 3-5. Phase 3 sẽ mở rộng (thêm async tool, tool permission, etc.) nhưng **không phá vỡ chữ ký cũ**.

## 3. Acceptance Criteria

Phase 2 hoàn thành khi **TẤT CẢ** các tiêu chí sau đạt:

### 3.1 Build & Runtime

- [ ] `dotnet build` thành công, không có warning.
- [ ] `docker compose up` vẫn chạy được (Phase 1 vẫn hoạt động, không bị regress).
- [ ] pgvector extension đã được cài trong PostgreSQL container.
- [ ] OpenAI API key có thể config qua env var (optional - nếu không có thì chỉ dùng Ollama).

### 3.2 Functional - Document Management

- [ ] Upload file PDF (≤ 10MB) qua API `POST /api/v1/documents` thành công.
- [ ] Upload file DOCX, TXT, MD cũng thành công.
- [ ] Sau upload, document có status `pending` → `processing` → `ready` (hoặc `failed`).
- [ ] Có thể list documents, filter theo status, pagination.
- [ ] Có thể delete document (cascading xóa chunks, embeddings).
- [ ] Frontend hiển thị được document list, upload progress, status.

### 3.3 Functional - RAG

- [ ] Sau khi upload PDF, có thể gọi `POST /api/v1/rag/query` với câu hỏi về nội dung PDF, nhận response có citation.
- [ ] Citation hiển thị đúng: tên file, page number (nếu có), text snippet.
- [ ] Streaming RAG query hoạt động: từng token hiển thị từ từ.
- [ ] Nếu không tìm thấy context liên quan, RAG trả "Tôi không tìm thấy thông tin phù hợp" (không hallucinate).
- [ ] Top-K config được: trả về đúng số chunks.

### 3.4 Functional - Multi-Provider

- [ ] Có thể config trong tenant config: dùng Ollama hay OpenAI.
- [ ] Khi switch sang OpenAI, chat hoạt động bình thường.
- [ ] Khi OpenAI API key sai, hệ thống báo lỗi rõ ràng (không crash).
- [ ] Khi OpenAI down/timeout, có thể fallback sang Ollama (nếu config).
- [ ] Health check cho tất cả providers chạy mỗi 30s.

### 3.5 Functional - Tools

- [ ] Có ít nhất 3 built-in tools: `calculator`, `current_time`, `web_search` (mock).
- [ ] `GET /api/v1/tools` trả về danh sách tools có sẵn.
- [ ] `POST /api/v1/tools/calculator/call` với args `{expression: "2+2*3"}` trả `{result: 8}`.
- [ ] Tool call được log vào DB (audit trail cơ bản).
- [ ] Tool call có timeout (mặc định 10s).

### 3.6 Code Quality

- [ ] Tất cả interface mới có XML doc comment.
- [ ] Mỗi public class mới có unit test, coverage ≥ 60%.
- [ ] Integration test cho upload → index → query flow.
- [ ] Không có secret/API key hardcoded (đọc từ config/env).
- [ ] Code tuân thủ convention Phase 1 đã chốt.

### 3.7 Backward Compatibility

- [ ] Phase 1 vẫn chạy được (chat không RAG, chỉ Ollama).
- [ ] Database migration Phase 1 không bị ảnh hưởng (chỉ thêm bảng mới).
- [ ] API endpoints Phase 1 vẫn hoạt động như cũ.
- [ ] Frontend Phase 1 vẫn dùng được (chat không RAG).

### 3.8 Documentation

- [ ] CHANGELOG.md cập nhật v0.2.0.
- [ ] README cập nhật hướng dẫn upload document, RAG, multi-provider.
- [ ] File `02.PHASE_01_FOUNDATION.md` được tham chiếu đúng.
- [ ] File phase này (`03.PHASE_02_AI_ENGINE_RAG.md`) đã tạo.
- [ ] Thêm ADR mới nếu có quyết định mới (VD: chọn iText7 cho PDF parser).

### 4.3 Luồng RAG Query (chi tiết)

```
User hỏi: "Công ty có bao nhiêu ngày phép năm?"
                       │
                       ▼
┌──────────────────────────────────────────────────────────┐
│ 1. RagEndpoints.Query (hoặc StreamQuery)                  │
│    - Lấy userId, tenantId từ JWT context                 │
│    - Validate request                                     │
└────────────────────┬─────────────────────────────────────┘
                     │
                     ▼
┌──────────────────────────────────────────────────────────┐
│ 2. RAGEngine.QueryAsync                                  │
│    a. Embed query: IEmbeddingProvider.EmbedAsync(text)   │
│       → float[768] (Ollama nomic) hoặc float[1536] (OpenAI)│
│    b. Retrieve: IRetriever.SearchAsync(queryVector, topK)│
│       → list of (chunk, score, metadata)                │
│    c. Filter theo MinScore                               │
│    d. Build context: PromptBuilder                        │
│       → "Context: <chunk 1>\n<chunk 2>\n...\n\n          │
│          Question: <query>\n\n                           │
│          Answer based on context above."                 │
│    e. Add system prompt: "You are a helpful AI..."       │
│    f. Call LLM: ILLMProvider.StreamChatAsync(request)    │
│    g. Stream delta về frontend                            │
│    h. Accumulate citations trong khi stream              │
│    i. Save RagQueryLog                                    │
└────────────────────┬─────────────────────────────────────┘
                     │
                     ▼
┌──────────────────────────────────────────────────────────┐
│ 3. Return RAGResponse                                    │
│    - Answer: text từ LLM                                 │
│    - Citations: [1] doc1.pdf p.5, [2] policy.md ...     │
│    - Metrics: latency, tokens, retrieved chunks          │
└──────────────────────────────────────────────────────────┘
```

### 4.4 Luồng Document Ingestion

```
Client upload PDF qua POST /api/v1/documents
                       │
                       ▼
┌──────────────────────────────────────────────────────────┐
│ 1. DocumentEndpoints.Upload                             │
│    - Validate file (size, mime type)                     │
│    - Lưu raw file vào MinIO                              │
│    - Tạo DocumentEntity status=pending                   │
│    - Enqueue vào DocumentIndexingQueue                    │
│    - Return documentId                                   │
└────────────────────┬─────────────────────────────────────┘
                     │
                     ▼ (background)
┌──────────────────────────────────────────────────────────┐
│ 2. DocumentIndexingWorker (IHostedService)               │
│    - Polling queue                                       │
│    - Cho mỗi documentId:                                │
│      a. Update status = processing                       │
│      b. Download file từ MinIO                            │
│      c. IDocumentParser.ParseAsync()                      │
│         → Plain text + metadata (page, title, ...)       │
│      d. IChunker.ChunkAsync(text)                         │
│         → List<Chunk>                                    │
│      e. Với mỗi chunk:                                   │
│         - IEmbeddingProvider.EmbedAsync(chunk.Text)       │
│         - IVectorStore.UpsertAsync(vector)                │
│      f. Lưu ChunkEntity + EmbeddingEntity vào DB         │
│      g. Update status = ready                            │
│    - Nếu fail: status = failed, lưu error_message        │
│    - Retry tối đa 3 lần với exponential backoff          │
└──────────────────────────────────────────────────────────┘
```

### 7.1 Bảng mới

```sql
-- Bảng collections: nhóm document (per tenant)
CREATE TABLE collections (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    name            VARCHAR(200) NOT NULL,
    description     TEXT,
    embedding_model VARCHAR(100) NOT NULL,        -- 'nomic-embed-text' | 'text-embedding-3-small'
    embedding_dim   INT NOT NULL,                 -- 768 | 1536
    chunk_size      INT NOT NULL DEFAULT 512,
    chunk_overlap   INT NOT NULL DEFAULT 50,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_collections_tenant ON collections(tenant_id);

-- Bảng documents: tài liệu được upload
CREATE TABLE documents (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    collection_id   UUID REFERENCES collections(id) ON DELETE SET NULL,
    uploaded_by     UUID NOT NULL REFERENCES users(id),
    
    -- Source info
    source_filename VARCHAR(500) NOT NULL,
    source_mime     VARCHAR(100) NOT NULL,
    source_size     BIGINT NOT NULL,              -- bytes
    source_uri      VARCHAR(1000),                -- minio path: 'documents/{tenantId}/{docId}.pdf'
    source_hash     VARCHAR(128),                 -- SHA-256, dedup
    
    -- Parsed info
    title           VARCHAR(500),
    language        VARCHAR(10),
    page_count      INT,
    word_count      INT,
    
    -- Processing status
    status          VARCHAR(20) NOT NULL DEFAULT 'pending',  -- 'pending' | 'processing' | 'ready' | 'failed'
    error_message   TEXT,
    chunk_count     INT DEFAULT 0,
    
    -- Metadata
    tags            TEXT[],
    metadata        JSONB,
    
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    indexed_at      TIMESTAMPTZ
);

CREATE INDEX idx_documents_tenant_status ON documents(tenant_id, status);
CREATE INDEX idx_documents_collection ON documents(collection_id);
CREATE INDEX idx_documents_uploaded_by ON documents(uploaded_by);

-- Bảng chunks: từng đoạn text đã được chunk
CREATE TABLE chunks (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    document_id     UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    chunk_index     INT NOT NULL,                 -- vị trí trong document
    content         TEXT NOT NULL,
    token_count     INT NOT NULL,
    char_count      INT NOT NULL,
    page_number     INT,
    section         VARCHAR(500),                 -- heading/section
    metadata        JSONB,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_chunks_document ON chunks(document_id, chunk_index);
CREATE INDEX idx_chunks_tenant ON chunks(tenant_id);

-- Bảng embeddings: vector embedding của chunks
CREATE TABLE embeddings (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    chunk_id        UUID NOT NULL UNIQUE REFERENCES chunks(id) ON DELETE CASCADE,
    collection_id   UUID NOT NULL REFERENCES collections(id) ON DELETE CASCADE,
    model_id        VARCHAR(100) NOT NULL,
    dimensions      INT NOT NULL,
    vector          VECTOR(1536) NOT NULL,        -- pgvector type
    embedded_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Index cho vector search (IVFFlat - Phase 2 dùng lists = 100)
CREATE INDEX idx_embeddings_vector ON embeddings USING ivfflat (vector vector_cosine_ops) WITH (lists = 100);
CREATE INDEX idx_embeddings_chunk ON embeddings(chunk_id);
CREATE INDEX idx_embeddings_collection ON embeddings(collection_id);
CREATE INDEX idx_embeddings_tenant ON embeddings(tenant_id);

-- Bảng tool_definitions: catalog các tool (built-in + custom)
CREATE TABLE tool_definitions (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID,                        -- NULL = global built-in
    name            VARCHAR(100) NOT NULL,
    description     TEXT NOT NULL,
    parameters_schema JSONB NOT NULL,
    category        VARCHAR(50),                 -- 'search' | 'action' | 'query' | 'utility'
    is_builtin      BOOLEAN NOT NULL DEFAULT false,
    is_enabled      BOOLEAN NOT NULL DEFAULT true,
    timeout_seconds INT NOT NULL DEFAULT 10,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE(tenant_id, name)                      -- per-tenant unique name
);

-- Bảng tool_calls: log mỗi lần gọi tool
CREATE TABLE tool_calls (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    user_id         UUID REFERENCES users(id),
    session_id      UUID REFERENCES chat_sessions(id) ON DELETE SET NULL,
    tool_name       VARCHAR(100) NOT NULL,
    arguments_json  TEXT,
    result_json     TEXT,
    success         BOOLEAN NOT NULL,
    error_message   TEXT,
    duration_ms     INT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_tool_calls_tenant_time ON tool_calls(tenant_id, created_at DESC);
CREATE INDEX idx_tool_calls_user ON tool_calls(user_id, created_at DESC);
CREATE INDEX idx_tool_calls_tool_name ON tool_calls(tool_name);

-- Bảng rag_query_logs: log mỗi RAG query
CREATE TABLE rag_query_logs (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    user_id         UUID REFERENCES users(id),
    session_id      UUID REFERENCES chat_sessions(id) ON DELETE SET NULL,
    collection_id   UUID REFERENCES collections(id) ON DELETE SET NULL,
    
    query_text      TEXT NOT NULL,
    strategy        VARCHAR(20) NOT NULL,        -- 'vector' | 'hybrid'
    top_k           INT NOT NULL,
    
    -- Retrieval results
    retrieved_chunks JSONB,                      -- [{chunkId, score, documentId, ...}]
    citation_count  INT,
    
    -- Generation results
    answer_text     TEXT,
    model_id        VARCHAR(100),
    provider_id     VARCHAR(50),
    
    -- Metrics
    retrieval_ms    INT,
    llm_ms          INT,
    total_ms        INT,
    prompt_tokens   INT,
    completion_tokens INT,
    total_tokens    INT,
    
    -- Feedback (optional, sẽ dùng ở Phase 4+)
    user_rating     INT,                         -- 1-5
    user_feedback   TEXT,
    
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_rag_logs_tenant_time ON rag_query_logs(tenant_id, created_at DESC);
CREATE INDEX idx_rag_logs_session ON rag_query_logs(session_id);
CREATE INDEX idx_rag_logs_user ON rag_query_logs(user_id, created_at DESC);

## 9. Luồng End-to-End mới

### 9.1 Luồng Upload Document

```
User ở /documents, kéo thả file PDF vào dropzone
                       │
                       ▼
1. Frontend DocumentUploader component:
   - Validate file (size ≤ 10MB, mime type trong whitelist)
   - Tạo FormData
   - POST /api/v1/documents
                       │
                       ▼
2. Backend DocumentEndpoints.Upload:
   - Lấy userId, tenantId từ JWT
   - Lưu file vào MinIO: documents/{tenantId}/{uuid}.pdf
   - Tính SHA-256 hash
   - Check duplicate (cùng hash trong tenant → trả existing)
   - Tạo DocumentEntity status=pending
   - Enqueue documentId vào DocumentIndexingQueue
   - Return 201 Created
                       │
                       ▼
3. Frontend: 
   - Hiển thị document card với status badge "pending"
   - Subscribe SSE hoặc poll GET /api/v1/documents/{id} mỗi 2s
                       │
                       ▼ (background)
4. DocumentIndexingWorker:
   - Polling queue
   - Set status = processing
   - Download file từ MinIO
   - PdfDocumentParser.ParseAsync() → text + page info
   - RecursiveChunker.ChunkAsync(text) → list of Chunk
   - Với mỗi chunk:
     a. Save ChunkEntity
     b. OllamaEmbeddingProvider.EmbedAsync(chunk.Content)
     c. PgVectorStore.UpsertAsync(vector record)
     d. Save EmbeddingEntity
   - Set status = ready, indexedAt = now
   - Nếu fail: status = failed, error_message = "..."
   - Retry 3 lần nếu fail
                       │
                       ▼
5. Frontend:
   - Status update → "ready", hiển thị chunk count
   - User có thể click vào document để xem chunks (debug)
```

### 9.2 Luồng RAG Query (Streaming)

```
User ở /chat, bật toggle "Use RAG", chọn collection "HR Documents", gõ câu hỏi
                       │
                       ▼
1. Frontend useStreamRagQuery hook:
   - Build request: {query, collectionId, topK, strategy, sessionId}
   - POST /api/v1/rag/query/stream
   - Mở SSE stream
                       │
                       ▼
2. Backend RagEndpoints.StreamQuery:
   - Validate request
   - Lấy userId, tenantId từ context
   - Lấy collectionId → verify thuộc tenant
                       │
                       ▼
3. RAGEngine.StreamQueryAsync:
   a. Start timer
   b. Embed query:
      - IEmbeddingProvider.EmbedAsync(query) → vector
      - Log embedding latency
   c. Retrieve:
      - IRetriever.SearchAsync(vector, topK, collectionId)
      - Trả về list of (chunk, score, metadata)
   d. Build prompt:
      - System: "You are a helpful AI assistant. Answer based on context below."
      - Context: "[1] <chunk1 content>\n[2] <chunk2 content>..."
      - User: "<query>"
   e. LLM generation:
      - ILLMProvider.StreamChatAsync(chatRequest)
      - Stream từng delta
      - Accumulate content
   f. Build citations:
      - Từ retrieved chunks, build list of Citation
   g. Save RagQueryLog
   h. Yield stream chunks:
      - "retrieval_complete" event với citations + retrieval metrics
      - Mỗi "chunk" event với delta
      - "done" event với final metrics
                       │
                       ▼
4. Frontend nhận SSE:
   - Hiển thị citation ngay khi có (dưới message, collapsible)
   - Append từng token vào bubble
   - Hiển thị progress + metrics cuối
```

Tenant config:

   │
   ▼

   │
   ▼
ProviderMetricsTracker.Record(ProviderId, Latency, Tokens, Error)
```

## Phụ lục A: Common Pitfalls & Solutions

### A.1 pgvector extension chưa cài

**Vấn đề**: Migration fail vì extension `vector` chưa có.

**Giải pháp**:
```sql
-- Trong migration hoặc init script:
CREATE EXTENSION IF NOT EXISTS vector;
```

Hoặc trong docker-compose:
```yaml
postgres:
  image: pgvector/pgvector:pg16
```

### A.2 OpenAI API key không có

**Vấn đề**: User chưa config OpenAI key, nhưng code cố gọi.

**Giải pháp**:
- Make OpenAI provider optional: nếu không có API key, skip trong DI.
- Config check: `if (string.IsNullOrEmpty(openAiOptions.ApiKey)) return;`
- Tenant config: cho phép tenant không chọn OpenAI.

### A.3 PDF parsing chậm với file lớn

**Vấn đề**: PDF 100 trang mất 30s+ để parse.

**Giải pháp**:
- Background job (đã làm).
- Streaming parse: đọc từng trang, không load toàn bộ.
- Timeout: 60s, fail nếu quá.

### A.4 Chunking tạo ra chunks quá ngắn hoặc quá dài

**Vấn đề**: Chunk 10 từ (quá ngắn, không có context) hoặc chunk 5000 từ (quá dài, vượt embedding model limit).

**Giải pháp**:
- Config: min_chunk_size = 50 tokens, max_chunk_size = 1000 tokens.
- RecursiveChunker: ưu tiên split theo paragraph trước, sentence sau, word cuối.
- Validate: nếu chunk quá dài, re-chunk nhỏ hơn.

### A.5 Vector search trả về kết quả không liên quan

**Vấn đề**: Embedding model không tốt, hoặc query và document ở 2 không gian ngữ nghĩa khác nhau.

**Giải pháp** (Phase 2 chưa xử lý hết, sẽ cải thiện ở Phase 4):
- Tăng topK (trả về nhiều candidates hơn).
- Filter theo MinScore (loại bỏ chunks có score thấp).
- Query rewriting (sẽ làm ở Phase 4 với Reranker).
- Hybrid search (Phase 4).

### A.6 MinIO không accessible từ backend

**Vấn đề**: Docker network isolation, backend không thấy MinIO.

**Giải pháp**:
- Cùng network `platform-net` trong docker-compose.
- Health check cho MinIO.
- Endpoint: `http://minio:9000` (từ backend trong compose), `http://localhost:9000` (từ host).

```yaml
minio:
  image: minio/minio:latest
  container_name: platform-minio
  environment:
    MINIO_ROOT_USER: minioadmin
    MINIO_ROOT_PASSWORD: minioadmin_dev_pwd
  ports:
    - "9000:9000"
    - "9001:9001"  # Console UI
  volumes:
    - minio-data:/data
  command: server /data --console-address ":9001"
  healthcheck:
    test: ["CMD", "mc", "ready", "local"]
    interval: 10s
    timeout: 5s
    retries: 5
  networks:
    - platform-net
```
