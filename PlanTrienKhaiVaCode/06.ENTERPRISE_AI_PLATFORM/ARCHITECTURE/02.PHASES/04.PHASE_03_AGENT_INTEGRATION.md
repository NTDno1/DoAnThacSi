# Phase 3: Agent & Integration

> **Mục tiêu**: Xây dựng **Agent Framework** (Intent Router, Task Planner, Agent Executor) cho phép AI thực hiện các tác vụ phức tạp, đa bước. Tích hợp **MCP (Model Context Protocol)** để mở rộng khả năng AI. Xây dựng **Plugin SDK** cho phép bên thứ ba mở rộng platform. Hoàn thiện **REST/gRPC Gateway** với đầy đủ API. Tích hợp **Message Queue** và **Event Bus** cho kiến trúc event-driven.
>
> **Demo cuối phase**: User ra lệnh phức tạp "Tạo đơn nghỉ phép cho tôi từ 20/06 đến 22/06, manager là Nguyễn Văn A" → Agent phân tích intent → lập plan nhiều bước → execute từng bước → gọi tool MCP để tra cứu HR → tạo ticket. Ngoài ra có thể load plugin từ folder plugins/ để thêm tool mới.

## 1. Tổng quan Phase 3

### 1.1 Tại sao là Phase 3 này?

Phase 2 đã có RAG - cho phép AI trả lời câu hỏi dựa trên tài liệu. Nhưng đó mới chỉ là **question-answering**, chưa phải **task execution**. Một AI Agent thực sự cần:

- **Hiểu intent phức tạp**: "Tôi muốn tạo đơn nghỉ phép" không chỉ trả lời mà phải thực hiện.
- **Lập kế hoạch đa bước**: kiểm tra phép → tìm manager → tạo ticket → gửi thông báo.
- **Gọi nhiều tool theo thứ tự**: query DB, gọi API, gửi email.
- **Học hỏi từ lỗi**: nếu 1 bước fail, replan.

Phase 3 xây dựng **Agent Framework** giải quyết các vấn đề trên, đồng thời mở rộng khả năng tích hợp:
- **MCP**: cho phép AI gọi tool từ bất kỳ hệ thống nào hỗ trợ MCP (như Claude Desktop, các AI client khác).
- **Plugin SDK**: cho phép developer viết plugin mới (custom tool, custom parser) mà không cần build lại platform.
- **REST + gRPC Gateway**: API hoàn chỉnh cho cả web client (REST) và internal service (gRPC).
- **Message Queue + Event Bus**: hỗ trợ async task, workflow phức tạp, decoupling giữa các service.

### 1.2 Tóm tắt kỹ thuật

| Thành phần | Phase 2 → Phase 3 |
|------------|-------------------|
| Agent Framework | Chưa có → Intent Router + Task Planner + Agent Executor + Replan on failure |
| Tool Calling | Single tool call → Multi-step tool orchestration với parallel, sequential, conditional |
| MCP | Chưa có → MCP Server (expose tools) + MCP Client (call external MCP) |
| Plugin SDK | Chưa có → Plugin loader, hot-reload, security sandbox |
| Gateway | Chỉ REST → REST + gRPC (internal high-perf) |
| API | Đủ cho RAG → Đầy đủ cho Agent (run, pause, resume, cancel, subscribe events) |
| Message Queue | Chưa có → RabbitMQ + worker cho async task |
| Event Bus | Chưa có → In-process MediatR + RabbitMQ cho cross-process |
| Real-time Update | Polling → SignalR cho agent run progress |
| CI/CD | Chưa có → GitHub Actions workflow cơ bản |

## 2. Phạm vi & Không phạm vi

### 2.1 Trong phạm vi (In Scope)

✅ **Intent Router**:
- `IIntentRouter` interface.
- 2 strategy: Rule-based (keyword matching) + LLM-based (few-shot classification).
- Intent taxonomy mặc định: `simple_chat`, `qa` (RAG), `task_execution`, `data_query`, `chitchat`, `out_of_scope`.
- Configuration trong DB (per-tenant), có thể custom intent mới.

✅ **Task Planner**:
- `ITaskPlanner` interface.
- `PlanAndExecutePlanner`: dùng LLM sinh plan (chain-of-thought).
- Plan = danh sách steps, mỗi step có: type (tool/agent/conditional), tool_name, params, depends_on, requires_approval.
- Output format: structured JSON.
- Validation: kiểm tra dependency cycle, tool tồn tại, schema params hợp lệ.

✅ **Agent Executor**:
- `IAgentExecutor` interface.
- State machine cho từng step: PENDING → RUNNING → DONE/FAILED/AWAITING_HUMAN.
- Sequential execution theo DAG (steps độc lập chạy parallel).
- Retry với exponential backoff (max 3 lần / step).
- Replan khi fail không retry được.
- Track metrics: step duration, total run duration, retry count.
- Event emission: mỗi state transition phát event qua Event Bus.

✅ **Tool Engine mở rộng**:
- Async tool support (`Task<ToolResult>` thay vì `ToolResult`).
- Tool categories: `search`, `action`, `query`, `utility`, `integration`.
- Tool permissions: per-tenant whitelist/blacklist.
- Tool approval flag (cho tool nguy hiểm).
- Async long-running tool qua message queue.

✅ **MCP Server (phía platform)**:
- Implement MCP protocol (JSON-RPC 2.0).
- Transport: HTTP+SSE (cho web), stdio (cho local client).
- Expose platform tools dưới dạng MCP endpoints.
- Authentication: Bearer token.
- Có thể test qua Claude Desktop hoặc MCP client khác.

✅ **MCP Client**:
- Gọi external MCP servers.
- Config: endpoint URL, auth token, transport.
- Auto-discover tools khi kết nối.
- Cache tool definitions.

✅ **Plugin SDK**:
- `IPlugin` interface, `IPluginContext` để plugin tương tác với platform.
- Plugin types: `IToolPlugin`, `IConnectorPlugin`, `IDocumentParserPlugin`.
- `IPluginLoader` quản lý load/unload/hot-reload.
- Plugin manifest (plugin.json) chứa metadata, version, dependencies.
- Plugin security: load trong AppDomain riêng, permission set giới hạn.
- Watch folder `./plugins/`, auto load khi có file mới.
- Plugin config per-tenant (DB).

✅ **REST Gateway mở rộng**:
- Agent endpoints: `POST /api/v1/agents/run`, `GET /api/v1/agents/runs/{id}`, `POST /api/v1/agents/runs/{id}/pause`, `POST /api/v1/agents/runs/{id}/resume`, `POST /api/v1/agents/runs/{id}/cancel`.
- SSE stream cho agent run events.
- MCP endpoints: `GET /api/v1/mcp/tools` (proxy to MCP server), `POST /api/v1/mcp/call` (gọi tool qua MCP).
- Plugin admin endpoints: `GET /api/v1/admin/plugins`, `POST /api/v1/admin/plugins/{id}/enable`, etc.
- Health check mở rộng: kiểm tra MCP servers, plugins, message queue.

✅ **gRPC Gateway (MỚI)**:
- gRPC service definitions (proto files).
- gRPC server implement cho internal service: `ChatService`, `AgentService`, `RAGService`.
- gRPC client (cho internal microservice communication khi cần).
- Tích hợp với REST gateway (cùng business logic, 2 protocol).

✅ **Message Queue**:
- RabbitMQ container trong docker-compose.
- `IMessagePublisher` + `IMessageConsumer` abstraction.
- Implementations: RabbitMQ.
- Queues: `agent.steps`, `documents.reindex`, `notifications.outbound`.
- Reliability: ack/nack, DLQ, retry.
- CloudEvents spec cho message format.

✅ **Event Bus**:
- `IDomainEventBus` abstraction.
- In-process: MediatR.
- Cross-process: RabbitMQ.
- Domain events: `DocumentIndexed`, `ChatMessageCreated`, `AgentRunCompleted`, `ToolCallExecuted`, `ProviderFailover`, etc.
- Versioning: `DocumentIndexed.v1`.

✅ **Real-time (SignalR)**:
- SignalR Hub: `AgentHub` cho client subscribe agent run progress.
- Push events: step started, step completed, step failed, run completed.
- Authentication: JWT (SignalR support).
- Frontend sử dụng `@microsoft/signalr` client.

✅ **Persistence mở rộng**:
- Entities mới: `AgentRunEntity`, `AgentPlanEntity`, `AgentPlanStepEntity`, `PluginEntity`, `McpEndpointEntity`, `AgentEventEntity`, `ToolPermissionEntity`.
- Migration: `Add_Agent_MCP_Plugins`.

✅ **CI/CD**:
- GitHub Actions workflow: lint, build, test, docker build.
- Matrix: ubuntu, windows.
- Cache NuGet packages.
- Upload test results, coverage.

✅ **Frontend mở rộng**:
- Trang `/agents/runs`: list agent runs của user.
- Trang `/agents/runs/{id}`: plan viewer (DAG), step progress (real-time qua SignalR), log.
- Trang `/agents/runs/{id}/events`: event stream.
- Trang `/admin/plugins` (chỉ admin): list plugins, enable/disable, config.
- Trang `/mcp` (advanced): test MCP tools.
- Tool execution trong chat: hiển thị "đang gọi tool X" + kết quả.

✅ **Tests mở rộng**:
- Unit test: IntentRouter, PlanAndExecutePlanner, AgentExecutor, MCPServer, MCPClient, PluginLoader, EventBus.
- Integration test: agent run end-to-end, MCP tool call, plugin load.
- E2E test: chat → agent run → tool call → completion.

### 2.2 Ngoài phạm vi (Out of Scope)

❌ HITL UI + notification (email, slack) đầy đủ - chỉ có interface stub.
❌ Safety guardrails (prompt injection detection, PII masking, output filtering) - chỉ có structure.

❌ Memory manager (long-term) - chỉ short-term qua chat session.
❌ Voice (STT/TTS).
❌ SQL Engine (text-to-SQL).
❌ Workflow engine (multi-step với conditionals phức tạp).
❌ External connectors (ERP, CRM, HRM, BI) - chỉ sample.
❌ Rate limiting - chưa cần.
❌ Provider cache (LLM response cache) - chưa cần.
❌ Anthropic, Azure OpenAI, Gemini providers - chỉ Ollama + OpenAI.

```csharp
public interface ITaskPlanner
{
    Task<Plan> CreatePlanAsync(PlanningRequest request, CancellationToken ct);

public record PlanningRequest(
    string Goal,
    Guid TenantId,

    string? Reasoning,                     // chain-of-thought

    StepStatus Status,
    string? Output,
    string? ErrorMessage,
    int AttemptCount,

    DateTime? CompletedAt,
    int? DurationMs
);

public record AgentEvent(
    Guid RunId,
    Guid? StepIndex,
    AgentEventType Type,
    DateTime OccurredAt,
    object Data

    StepStarted, StepCompleted, StepFailed, StepRetried, StepAwaitingHuman,
```

## 3. Acceptance Criteria

Phase 3 hoàn thành khi **TẤT CẢ** các tiêu chí sau đạt:

### 3.1 Build & Runtime

- [ ] `dotnet build` thành công, không có warning.
- [ ] `docker compose up` chạy được với service mới: `rabbitmq` (thêm vào compose).
- [ ] RabbitMQ Management UI accessible tại `http://localhost:15672`.
- [ ] Phase 1 + Phase 2 vẫn hoạt động (chat + RAG + tools).
- [ ] gRPC server chạy được (port 5001), test qua grpcurl hoặc client.

### 3.2 Functional - Intent Classification

- [ ] Câu hỏi "Xin chào" → intent = `chitchat`, handler = `chat`.
- [ ] Câu hỏi "Quy chế nghỉ phép là gì?" → intent = `qa`, handler = `rag`.
- [ ] Câu hỏi "Tạo đơn nghỉ phép cho tôi" → intent = `task_execution`, handler = `agent`.
- [ ] Câu hỏi "Doanh thu Q3?" → intent = `data_query`, handler = `sql` (Phase 4 mới dùng thật, Phase 3 dùng mock).
- [ ] Confidence score được trả về đúng.
- [ ] LLM-based intent classification hoạt động khi rule không match.

### 3.3 Functional - Task Planning

- [ ] Goal "Tạo đơn nghỉ phép" → plan gồm 3-5 steps (check phép, tìm manager, tạo ticket, gửi thông báo).
- [ ] Plan được validate: không có dependency cycle, tools tồn tại, params đúng schema.
- [ ] LLM sinh plan có chain-of-thought reasoning.
- [ ] Replan khi 1 step fail: tạo plan mới với context từ failure.

### 3.4 Functional - Agent Execution

- [ ] Agent run start thành công, có `runId`.
- [ ] Steps chạy theo thứ tự dependency.
- [ ] Steps độc lập chạy parallel.
- [ ] Tool call được thực thi, kết quả được lưu vào step output.
- [ ] Step fail → retry với exponential backoff.
- [ ] Retry fail → trigger replan.
- [ ] User có thể pause/resume/cancel run.
- [ ] Run completed → có metrics (duration, step count, retry count).

### 3.5 Functional - Real-time Update

- [ ] Frontend subscribe được agent run qua SignalR.
- [ ] Mỗi step transition (started, completed, failed) được push tới client.
- [ ] UI update real-time không cần refresh.
- [ ] Multiple client subscribe cùng run đều nhận events.

### 3.6 Functional - MCP Server

- [ ] MCP server chạy được, expose platform tools.
- [ ] Claude Desktop (hoặc MCP Inspector) có thể kết nối và list tools.
- [ ] Gọi tool qua MCP thành công, response đúng format.
- [ ] Authentication: Bearer token hoạt động.
- [ ] Có thể test qua `/api/v1/mcp/tools` (REST proxy).

### 3.7 Functional - MCP Client

- [ ] Platform có thể kết nối tới external MCP server.
- [ ] Auto-discover tools khi connect.
- [ ] Gọi tool external MCP thành công.
- [ ] Cache tool definitions.
- [ ] Reconnect on disconnect.

### 3.8 Functional - Plugin System

- [ ] Sample plugin (file `MyPlugin.dll` + `plugin.json`) copy vào folder `plugins/` → auto loaded.
- [ ] Plugin tool xuất hiện trong `GET /api/v1/tools`.
- [ ] Plugin có thể được enable/disable per-tenant qua admin API.
- [ ] Sửa code plugin, recompile, copy lại → hot reload (tool mới xuất hiện).
- [ ] Plugin crash → không ảnh hưởng core, có log rõ ràng.
- [ ] Plugin không có quyền → bị reject khi load.

### 3.9 Functional - Message Queue

- [ ] RabbitMQ container chạy được.
- [ ] Publish message → consumer nhận được.
- [ ] Message có DLQ khi fail N lần.
- [ ] Async long-running tool qua message queue.
- [ ] Consumer có retry logic với exponential backoff.

### 3.10 Functional - Event Bus

- [ ] Domain event `DocumentIndexed` được publish khi document xong index.
- [ ] In-process subscriber (cùng service) nhận được.
- [ ] Cross-process subscriber (consumer service) nhận được qua RabbitMQ.
- [ ] Multiple subscribers cùng nhận event.

### 4.3 Luồng Agent Run (chi tiết)

```
User ở /chat gõ: "Tạo đơn nghỉ phép cho tôi từ 20/06 đến 22/06"
                       │
                       ▼
1. Frontend: POST /api/v1/chat (với intent = task_execution)
   Hoặc trực tiếp POST /api/v1/agents/run với goal
                       │
                       ▼
2. Backend AgentEndpoints.Run:
   - Lấy userId, tenantId
   - Tạo session (nếu chưa có)
   - Save user message
                       │
                       ▼
3. IntentRouter.ClassifyAsync:
   - Rule check: "tạo đơn" → match task_execution
   - Confidence 0.95, handler = "agent"
                       │
                       ▼
4. TaskPlanner.CreatePlanAsync:
   - LLM sinh plan (chain-of-thought):
     [
       { step 1: "Lấy số ngày phép còn lại", tool: "execute_sql", params: {query: "SELECT remaining_leave_days FROM employees WHERE user_id = :id"} },
       { step 2: "Lấy thông tin manager", tool: "execute_sql", params: {query: "SELECT manager_id FROM employees WHERE user_id = :id"}, dependsOn: [1] },
       { step 3: "Tạo ticket", tool: "create_ticket", params: {title: "Xin nghỉ phép", from: "2026-06-20", to: "2026-06-22", approver: "{{step2.manager_id}}"}, dependsOn: [1, 2], requires_approval: true }
     ]
   - Validate: tools exist, params valid, no cycle
   - Save Plan + PlanSteps
                       │
                       ▼
5. AgentExecutor.StartAsync:
   - Tạo AgentRun (status: executing)
   - Save to DB
   - Step 1 ready → start
   - Step 2 waiting for step 1 → queued
   - Step 3 waiting for step 1, 2 → queued
                       │
                       ▼
6. For each step:
   a. Update status: RUNNING
   b. Emit event: StepStarted
   c. Call ITool.ExecuteAsync(...)
   d. ToolRegistry.ExecuteAsync:
      - Validate args schema
      - Check permission
      - Call actual tool (could be sync hoặc async qua MQ)
      - Log ToolCall
   e. Update step: DONE, save output
   f. Emit event: StepCompleted
   g. If error: retry với backoff
   h. If requires_approval: emit StepAwaitingHuman, pause run
                       │
                       ▼
7. When step 3 (requires_approval) reaches:
   - Agent run paused
   - HITL request created (stub in Phase 3, full ở Phase 5)
   - User sees approval request in UI
                       │
                       ▼
8. User approves (Phase 3 manual, Phase 5 fully automated):
   - POST /api/v1/agents/runs/{id}/resume (với approval=true)
   - Step 3 continues
                       │
                       ▼
9. All steps done:
   - AgentRun status = Completed
   - Save final assistant message to chat session
   - Emit event: RunCompleted
   - Send notification (email/slack, Phase 5 full)
                       │
                       ▼
10. Frontend SignalR nhận events real-time:
    - UI update: plan viewer show step status
    - Final message: "Đơn nghỉ phép của bạn đã được tạo, đang chờ manager duyệt"
```

## 7. Data Model mở rộng

### 7.1 Bảng mới

```sql
-- Bảng agent_plans: lưu plan đã sinh
CREATE TABLE agent_plans (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    user_id         UUID NOT NULL REFERENCES users(id),
    session_id      UUID REFERENCES chat_sessions(id) ON DELETE SET NULL,
    goal            TEXT NOT NULL,
    status          VARCHAR(20) NOT NULL DEFAULT 'draft',   -- 'draft' | 'approved' | 'executing' | 'completed' | 'failed' | 'cancelled'
    plan_json       JSONB NOT NULL,                          -- full plan as JSON (steps, dependencies, ...)
    replan_count    INT NOT NULL DEFAULT 0,
    parent_plan_id  UUID REFERENCES agent_plans(id),        -- for replans
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_agent_plans_tenant ON agent_plans(tenant_id, created_at DESC);
CREATE INDEX idx_agent_plans_session ON agent_plans(session_id);

-- Bảng agent_runs: mỗi lần execute plan
CREATE TABLE agent_runs (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    user_id         UUID NOT NULL REFERENCES users(id),
    session_id      UUID REFERENCES chat_sessions(id) ON DELETE SET NULL,
    plan_id         UUID NOT NULL REFERENCES agent_plans(id),
    
    status          VARCHAR(20) NOT NULL DEFAULT 'pending',  -- 'pending' | 'executing' | 'paused' | 'awaiting_human' | 'completed' | 'failed' | 'cancelled'
    current_step    INT,
    error_message   TEXT,
    
    started_at      TIMESTAMPTZ,
    completed_at    TIMESTAMPTZ,
    paused_at       TIMESTAMPTZ,
    
    -- Metrics
    total_steps     INT NOT NULL DEFAULT 0,
    completed_steps INT NOT NULL DEFAULT 0,
    failed_steps    INT NOT NULL DEFAULT 0,
    retry_count     INT NOT NULL DEFAULT 0,
    total_duration_ms INT,
    
    metadata        JSONB,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_agent_runs_tenant_status ON agent_runs(tenant_id, status);
CREATE INDEX idx_agent_runs_session ON agent_runs(session_id);
CREATE INDEX idx_agent_runs_user ON agent_runs(user_id, created_at DESC);

-- Bảng agent_plan_steps: execution state của mỗi step
CREATE TABLE agent_plan_steps (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    run_id          UUID NOT NULL REFERENCES agent_runs(id) ON DELETE CASCADE,
    step_index      INT NOT NULL,
    
    -- Step definition (snapshot từ plan)
    description     TEXT NOT NULL,
    step_type       VARCHAR(20) NOT NULL,                    -- 'tool' | 'agent' | 'conditional' | 'parallel' | 'loop' | 'human'
    tool_name       VARCHAR(100),
    tool_params     JSONB,
    depends_on      INT[],
    requires_approval BOOLEAN NOT NULL DEFAULT false,
    
    -- Execution state
    status          VARCHAR(20) NOT NULL DEFAULT 'pending',  -- 'pending' | 'running' | 'done' | 'failed' | 'awaiting_human' | 'skipped' | 'cancelled'
    attempt_count   INT NOT NULL DEFAULT 0,
    max_retries     INT NOT NULL DEFAULT 3,
    output          TEXT,
    error_message   TEXT,
    
    started_at      TIMESTAMPTZ,
    completed_at    TIMESTAMPTZ,
    duration_ms     INT,
    
    metadata        JSONB,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_agent_plan_steps_run ON agent_plan_steps(run_id, step_index);
CREATE INDEX idx_agent_plan_steps_status ON agent_plan_steps(run_id, status);

-- Bảng agent_events: event stream (cho real-time + audit)
CREATE TABLE agent_events (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    run_id          UUID NOT NULL REFERENCES agent_runs(id) ON DELETE CASCADE,
    step_index      INT,
    event_type      VARCHAR(50) NOT NULL,                    -- 'RunStarted', 'StepStarted', 'StepCompleted', ...
    event_data      JSONB,
    occurred_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_agent_events_run ON agent_events(run_id, occurred_at);
CREATE INDEX idx_agent_events_tenant ON agent_events(tenant_id, occurred_at DESC);

-- Bảng plugins: catalog plugin
CREATE TABLE plugins (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID,                                    -- NULL = global plugin
    plugin_id       VARCHAR(100) NOT NULL,                   -- 'com.example.myplugin'
    name            VARCHAR(200) NOT NULL,
    version         VARCHAR(20) NOT NULL,                    -- semantic version
    description     TEXT,
    author          VARCHAR(200),
    assembly_path   VARCHAR(500) NOT NULL,                   -- path to DLL
    manifest        JSONB,                                   -- plugin.json content
    capabilities    TEXT[],                                  -- ['tool', 'connector', 'parser']
    is_enabled      BOOLEAN NOT NULL DEFAULT true,
    is_loaded       BOOLEAN NOT NULL DEFAULT false,
    last_loaded_at  TIMESTAMPTZ,
    last_error      TEXT,
    config          JSONB,                                   -- per-plugin config
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE(tenant_id, plugin_id, version)
);

CREATE INDEX idx_plugins_tenant ON plugins(tenant_id);
CREATE INDEX idx_plugins_loaded ON plugins(is_loaded);

-- Bảng mcp_endpoints: cấu hình external MCP servers
CREATE TABLE mcp_endpoints (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID,                                    -- NULL = global
    name            VARCHAR(200) NOT NULL,
    url             VARCHAR(500) NOT NULL,                   -- 'https://mcp.example.com/sse' hoặc 'stdio://command args'
    transport       VARCHAR(20) NOT NULL,                    -- 'http+sse' | 'stdio'
    auth_token      VARCHAR(500),                            -- bearer token
    is_enabled      BOOLEAN NOT NULL DEFAULT true,
    is_connected    BOOLEAN NOT NULL DEFAULT false,
    last_connected_at TIMESTAMPTZ,
    last_error      TEXT,
    cached_tools    JSONB,                                   -- cache tool definitions
    config          JSONB,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_mcp_endpoints_tenant ON mcp_endpoints(tenant_id);
CREATE INDEX idx_mcp_endpoints_enabled ON mcp_endpoints(is_enabled);

-- Bảng hitl_requests (stub cho Phase 3, full ở Phase 5)
CREATE TABLE hitl_requests (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    run_id          UUID NOT NULL REFERENCES agent_runs(id) ON DELETE CASCADE,
    step_index      INT NOT NULL,
    title           VARCHAR(500) NOT NULL,
    description     TEXT,
    context_json    JSONB,
    status          VARCHAR(20) NOT NULL DEFAULT 'pending',  -- 'pending' | 'approved' | 'rejected' | 'expired'
    resolved_at     TIMESTAMPTZ,
    resolver_id     UUID REFERENCES users(id),
    resolution_note TEXT,
    expires_at      TIMESTAMPTZ,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_hitl_requests_tenant ON hitl_requests(tenant_id, status);
CREATE INDEX idx_hitl_requests_run ON hitl_requests(run_id);

-- Bảng tool_permissions: per-tenant tool whitelist/blacklist
CREATE TABLE tool_permissions (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    tool_name       VARCHAR(100) NOT NULL,
    permission      VARCHAR(20) NOT NULL,                    -- 'allow' | 'deny'
    reason          TEXT,
    granted_by      UUID REFERENCES users(id),
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE(tenant_id, tool_name)
);

CREATE INDEX idx_tool_permissions_tenant ON tool_permissions(tenant_id);
```

## 9. Luồng End-to-End mới

### 9.1 Luồng Agent Run (qua chat)

```
1. User ở /chat gõ "Tạo đơn nghỉ phép từ 20/06 đến 22/06"
2. Frontend POST /api/v1/chat
3. Backend:
   a. Save user message
   b. IntentRouter classify → task_execution (confidence 0.93)
   c. TaskPlanner.CreatePlanAsync → plan 3-5 steps
   d. Save plan
   e. AgentExecutor.StartAsync → run
   f. Return response với agentRunId
4. Frontend nhận response, tự động:
   a. Connect SignalR tới AgentHub
   b. Subscribe runId
   c. Mở PlanViewer hiển thị DAG
5. AgentExecutor chạy từng step:
   - Update DB
   - Emit event → SignalR → frontend update real-time
6. Step 3 (requires_approval) → status=awaiting_human
   - Event push to client
   - HITLApprovalDialog mở
7. User approve:
   - POST /api/v1/agents/runs/{id}/resume
   - Step 3 tiếp tục
8. All steps done:
   - Run status=completed
   - Final message saved to chat session
   - User thấy response "Đơn nghỉ phép đã tạo, đang chờ duyệt"
```

```
Developer tạo plugin mới:
```

## Phụ lục A: Common Pitfalls

### A.1 Plan có dependency cycle

**Vấn đề**: LLM sinh plan có step A depends_on B, B depends_on A.

**Giải pháp**: `PlanValidator` kiểm tra cycle bằng topological sort trước khi execute. Fail fast nếu có cycle.

### A.2 Plugin load gây crash app

**Vấn đề**: Plugin có bug, throw exception khi load → app crash.

**Giải pháp**: Try-catch trong `PluginLoader.LoadAsync`, log error, set plugin status=failed, không crash app.

### A.3 SignalR không nhận event real-time

**Vấn đề**: Event bus publish nhưng SignalR client không nhận.

**Giải pháp**:
- Verify `AgentEventBroadcaster` subscribe đúng event.
- Check SignalR connection (ping/pong).
- Browser console log event.

### A.4 MCP authentication fail

**Vấn đề**: Client gọi MCP nhưng 401.

**Giải pháp**:
- Verify JWT trong MCP message handler.
- Config CORS cho MCP endpoint.
- Log auth attempts.

### A.5 gRPC reflection không hoạt động

**Vấn đề**: `grpcurl` không list services.

**Giải pháp**: Enable gRPC reflection trong Program.cs: `builder.Services.AddGrpcReflection()`. Add to pipeline: `app.MapGrpcReflectionService()`.
