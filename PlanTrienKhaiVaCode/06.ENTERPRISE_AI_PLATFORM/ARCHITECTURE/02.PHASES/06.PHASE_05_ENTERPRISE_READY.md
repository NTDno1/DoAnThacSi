# Phase 5: Enterprise Ready

> **Mục tiêu**: Hoàn thiện platform ở mức **production-ready, enterprise-grade**: **Multi-tenancy thực sự** (với Row-Level Security), **RBAC + ABAC đầy đủ** (kiểm soát truy cập chi tiết), **Audit & Compliance** (SOC2/GDPR cơ bản), **Safety Guardrails** (PII detection, prompt injection, output filtering), **HITL đầy đủ** (notification email/Slack), **Production deployment** (Kubernetes manifests, Helm chart), **Monitoring stack** (Prometheus + Grafana), **Disaster Recovery** (backup/restore), **SSO** (OIDC).
>
> **Demo cuối phase**: Stakeholder thấy platform chạy trên Kubernetes cluster với multi-tenant isolation, mọi action được audit, mọi sensitive operation cần approval qua email, security check chặt chẽ, monitoring dashboard đầy đủ, backup/restore thành công.

## 1. Tổng quan Phase 5

### 1.1 Tại sao là Phase 5 này?

Phase 1-4 đã xây dựng platform với đầy đủ tính năng AI cốt lõi: chat, RAG, agent, MCP, plugin, workflow, voice, SQL, memory. Tuy nhiên, đó vẫn là **prototype/SMB-level**. Để trở thành sản phẩm **enterprise-grade** mà khách hàng lớn (ngân hàng, tập đoàn) có thể triển khai, cần:

- **Multi-tenancy thực sự**: Mỗi khách hàng là 1 tenant, dữ liệu tách biệt tuyệt đối. Trước đó chỉ là 1 tenant cứng.
- **Bảo mật doanh nghiệp**: SSO, RBAC phức tạp, audit log đầy đủ.
- **Compliance**: SOC2, GDPR cơ bản (right to be forgotten, data export).
- **An toàn AI**: Chống prompt injection, mask PII, phát hiện hallucination.
- **Triển khai production**: Kubernetes, monitoring, alerting, HA, DR.
- **Vận hành**: Runbook, on-call, SLO/SLA.

### 1.2 Tóm tắt kỹ thuật

| Thành phần | Phase 4 → Phase 5 |
|------------|-------------------|
| Multi-tenancy | 1 tenant cứng → Full multi-tenant với RLS, per-tenant DB/schema option |
| Auth | JWT HS256, 1 user → OAuth2/OIDC SSO + RBAC + ABAC + Multi-factor |
| Audit | Tool call log → Comprehensive audit log (SOC2-ready) |
| Safety | Không có → PII detection, prompt injection, output filtering, hallucination check |
| HITL | In-app dialog → Email + Slack notification + auto-escalation |
| Deployment | docker-compose → Kubernetes (Helm chart), CI/CD hoàn chỉnh |
| Monitoring | OpenTelemetry traces → Prometheus + Grafana + Jaeger + AlertManager |
| DR | Không có → Automated backup + cross-region replication + restore test |
| SSO | Không có → OIDC (Azure AD, Okta, Google Workspace) |
| Compliance | Không có → GDPR data export + right to be forgotten |

## 2. Phạm vi & Không phạm vi

### 2.1 Trong phạm vi (In Scope)

✅ **Multi-tenancy thực sự**:
- Tenant provisioning API (tạo tenant, seed data).
- Tenant lifecycle: create → active → suspended → deleted.
- Tenant isolation strategies:
  - Schema-per-tenant (default cho enterprise).
  - Database-per-tenant (premium tier).
  - Row-Level Security với `tenant_id` (free tier, fallback).
- Tenant resolution từ JWT, subdomain, header.
- Tenant context propagate qua toàn bộ hệ thống.
- Tenant-specific config: AI providers, rate limits, features.
- Tenant data export (GDPR portability).
- Tenant data deletion (GDPR right to be forgotten).

✅ **OAuth2/OIDC SSO**:
- Generic OIDC client (hỗ trợ Azure AD, Okta, Google Workspace, Keycloak).
- Authorization Code Flow + PKCE.
- User provisioning từ IdP (Just-In-Time).
- Group → Role mapping.
- Tenant có thể config OIDC riêng.

✅ **RBAC + ABAC**:
- Role: `super_admin`, `tenant_admin`, `org_admin`, `power_user`, `user`, `guest`.
- Permission: `resource:action` (e.g. `document:read`, `agent:execute`).
- Policy engine: kiểm tra `(role, resource, action, context)`.
- ABAC attributes: time, location, device, data sensitivity.
- Permission cache (Redis, TTL 5 phút).
- Admin UI để quản lý role, permission.

✅ **API Key Management**:
- Per-user API key (cho programmatic access).
- Per-tenant API key (cho service-to-service).
- Scoped key: chỉ truy cập resource cụ thể.
- Key rotation, expiration.
- Key usage tracking.

✅ **Audit Log**:
- Mọi action quan trọng được ghi: login, config change, data access, tool call, agent run, etc.
- Immutable log (append-only, có hash chain để chống tamper).
- PII masking trước khi log.
- Query API: filter theo tenant, user, time, action.
- Export CSV/JSON cho audit.
- Retention policy: 1 năm mặc định, configurable.

✅ **Safety Guardrails**:
- **PII Detection**: NER model (regex + ML) phát hiện email, số điện thoại, CMND, etc.
- **Prompt Injection Detection**: pattern matching + LLM classifier.
- **Output Filtering**: toxic content, harmful advice.
- **Hallucination Detection**: citation check, NLI model.
- **Action Validation**: kiểm tra action có nguy hiểm không (e.g. delete data, send email to external).
- **Guardrail middleware**: input + output.

✅ **HITL đầy đủ**:
- In-app notification (real-time qua SignalR).
- Email notification (SendGrid/SMTP).
- Slack notification (incoming webhook).
- Auto-escalation: nếu không phản hồi sau X phút → escalate manager.
- Timeout: HITL request tự expire sau 7 ngày.
- Audit trail: mọi approval/rejection được log.

✅ **Notification Service**:
- Email: SendGrid, SMTP, AWS SES.
- Slack: incoming webhook, Bolt SDK.
- Webhook: HTTP POST với HMAC signature.
- In-app: SignalR real-time.
- Template system (Razor / Handlebars).
- Retry logic, DLQ.

✅ **Secrets Management**:
- HashiCorp Vault adapter.
- Azure Key Vault adapter.
- AWS Secrets Manager adapter.
- Local dev: .env / User Secrets.
- Auto rotation: OpenAI keys, JWT signing keys.
- Encryption at rest: AES-256 cho sensitive fields.

✅ **GDPR Compliance**:
- Data Export API: user yêu cầu → export tất cả data của user → download ZIP.
- Right to be forgotten: xóa tất cả data của user (cascade qua các bảng).
- Data retention policy: tự động xóa data cũ theo config.
- Consent management: user đồng ý terms.
- Cookie consent (frontend).

✅ **Production Deployment**:
- Kubernetes manifests (namespace, deployment, service, ingress, configmap, secret).
- Helm chart (parameterized, dễ deploy lên nhiều env).
- Kustomize overlays (dev, staging, prod).
- HPA (Horizontal Pod Autoscaler) theo CPU + custom metrics.
- PDB (Pod Disruption Budget) cho HA.
- Network policies: chỉ allow traffic cần thiết.
- Pod security standards: restricted.
- TLS termination ở Ingress.
- Cert-manager cho Let's Encrypt.
- External Secrets Operator để sync từ Vault.

✅ **Monitoring Stack**:
- **Prometheus**: scrape metrics từ app, exporters.
- **Grafana**: dashboards cho SLO, usage, performance.
- **Jaeger**: distributed tracing.
- **Loki**: log aggregation.
- **AlertManager**: alert rules.
- **SLO/SLI**: define cho availability, latency, error rate.
- **Health check endpoint**: `/health/live`, `/health/ready`, `/health/startup`.

✅ **CI/CD hoàn chỉnh**:
- GitHub Actions:
  - PR: lint, test, build, security scan.
  - Main: build, test, deploy to staging, run E2E, manual approval, deploy to prod.
- Container image: build, push to registry, sign.
- Database migration: chạy tự động trước deploy.
- Rollback: auto rollback nếu health check fail.
- Blue-green hoặc canary deployment.

✅ **Disaster Recovery**:
- Automated backup: PostgreSQL (pg_dump + WAL archiving), MinIO (incremental).
- Backup schedule: full hàng ngày, incremental mỗi giờ.
- Cross-region replication (s3-compatible).
- Restore test: 2 lần/năm, tự động validate.
- RPO: 1 giờ, RTO: 4 giờ.

✅ **API mới**:
- Tenant: CRUD, suspend, delete, data export.
- Auth: OIDC callback, refresh, MFA setup.
- RBAC: role/permission CRUD.
- API Key: CRUD, rotate, revoke.
- Audit: query, export.
- Safety: config, test.
- Notification: list, send, template.
- Compliance: data export request, deletion request.
- Monitoring: SLO definition, alert rules.

✅ **Frontend mở rộng**:
- Admin: tenant management, user management, role/permission.
- Audit log viewer: search, filter, export.
- Safety: PII scan, test injection.
- Compliance: data export request, status.
- API Key management.

✅ **Tests mở rộng**:
- Unit test: MultiTenancy, RBAC, Audit, Safety, Notification, Secrets.
- Integration test: SSO flow, multi-tenant isolation, audit query, PII detection.
- Security test: OWASP ZAP, dependency scan, secret scan.
- Load test: 1000 concurrent users.
- DR test: backup/restore.

## 3. Acceptance Criteria

Phase 5 hoàn thành khi **TẤT CẢ** các tiêu chí sau đạt:

### 3.1 Build & Runtime

- [ ] `dotnet build` thành công, không warning.
- [ ] `docker compose up` chạy được Phase 1-5.
- [ ] Kubernetes manifests apply thành công (`kubectl apply -f k8s/`).
- [ ] Helm chart install thành công (`helm install platform ./helm`).
- [ ] Tất cả pods Ready, services accessible.

### 3.2 Functional - Multi-tenancy

- [ ] Tạo 2 tenant qua API.
- [ ] User của tenant A không thấy data của tenant B (verified qua API test).
- [ ] Tenant A xóa → data của A bị xóa cascade, data của B không ảnh hưởng.
- [ ] Data export của tenant A chứa đầy đủ data.
- [ ] Tenant config (provider, model) áp dụng riêng cho từng tenant.

### 3.3 Functional - Auth & RBAC

- [ ] OIDC login với Azure AD hoặc Keycloak thành công.
- [ ] User được provision tự động khi login lần đầu (JIT).
- [ ] Role `user` không thể gọi admin endpoint (403).
- [ ] Role `admin` có quyền admin.
- [ ] API key hoạt động, có thể rotate, revoke.
- [ ] Permission cache invalidation khi role thay đổi.

### 3.4 Functional - Audit

- [ ] Mọi action (login, data access, tool call, agent run) được audit log.
- [ ] Audit log immutable (cố tình sửa DB → fail với hash mismatch).
- [ ] Query API filter theo tenant, user, time, action.
- [ ] Export CSV chứa đầy đủ thông tin.
- [ ] PII trong log được masked.

### 3.5 Functional - Safety

- [ ] PII detection: input có email, SĐT → detected, masked.
- [ ] Prompt injection: "Ignore previous instructions" → detected, blocked.
- [ ] Output filter: toxic content → blocked.
- [ ] Hallucination check: RAG response không có citation → flag.
- [ ] Action validation: tool call `delete_database` → require approval.

### 3.6 Functional - HITL

- [ ] HITL request → gửi email cho user.
- [ ] Email chứa link approve/reject.
- [ ] User approve qua link → agent resume.
- [ ] User không phản hồi 24h → auto-escalate manager.
- [ ] Sau 7 ngày không phản hồi → auto-cancel.

### 3.7 Functional - Production Deployment

- [ ] K8s cluster chạy platform thành công.
- [ ] Ingress với TLS (Let's Encrypt).
- [ ] HPA scale theo CPU.
- [ ] PDB đảm bảo HA.
- [ ] Pod security standards: restricted.
- [ ] Network policies enforce.

### 3.8 Functional - Monitoring

- [ ] Prometheus scrape metrics.
- [ ] Grafana dashboard hiển thị SLO.
- [ ] Jaeger trace distributed qua services.
- [ ] Alert rule: error rate > 5% → PagerDuty.
- [ ] Health check: `/health/live`, `/health/ready`, `/health/startup`.

### 3.9 Functional - DR

- [ ] Backup tự động chạy hàng ngày.
- [ ] Restore từ backup thành công.
- [ ] RPO ≤ 1 giờ, RTO ≤ 4 giờ.
- [ ] Cross-region replication hoạt động.

### 3.10 Security

- [ ] OWASP ZAP scan: không có lỗi high/critical.
- [ ] Dependency scan: không có CVE cao.
- [ ] Secret scan: không có secret leak.
- [ ] Penetration test cơ bản pass.
- [ ] HTTPS enforced, HSTS header.
- [ ] CSP, X-Frame-Options, etc.

### 3.11 Code Quality

- [ ] Test coverage ≥ 70% cho business logic.
- [ ] E2E test cho critical flow.
- [ ] Load test 1000 concurrent users: latency P95 < 5s, error rate < 1%.
- [ ] Code tuân thủ convention.

### 3.12 Documentation

- [ ] CHANGELOG v1.0.0.
- [ ] README đầy đủ cho production.
- [ ] Runbook: deployment, monitoring, incident response, DR.
- [ ] ADR cho mọi quyết định production.
- [ ] Security whitepaper.
- [ ] Admin guide.

### 4.3 Multi-tenancy với RLS

```sql
-- Enable RLS trên tất cả bảng có tenant_id
ALTER TABLE documents ENABLE ROW LEVEL SECURITY;
ALTER TABLE documents FORCE ROW LEVEL SECURITY;  -- kể cả superuser

-- Policy: chỉ cho phép truy cập rows của tenant hiện tại
CREATE POLICY tenant_isolation_policy ON documents
    USING (tenant_id = current_setting('app.current_tenant_id')::UUID);

-- Backend set tenant context trước mỗi query:
SET app.current_tenant_id = '00000000-0000-0000-0000-000000000001';
```

### 4.4 Luồng SSO Login

```
1. User click "Login with Azure AD"
2. Frontend redirect → /api/v1/auth/oidc/azure/login
3. Backend OidcService:
   a. Build authorization URL với state, PKCE
   b. Redirect user → Azure AD
4. User login trên Azure AD
5. Azure AD redirect → /api/v1/auth/oidc/azure/callback?code=xxx
6. Backend OidcService:
   a. Exchange code → access token, id token
   b. Get user info từ Azure AD
   c. Provision user (nếu chưa có) - JIT
   d. Map groups → roles
   e. Issue platform JWT
   f. Return JWT
7. Frontend save token, redirect → /chat
```

### 4.5 Luồng PII Detection

```
1. User gửi message: "Email tôi là nguyen@company.com, SĐT 0912345678"
2. SafetyGuardrails.CheckInputAsync:
   a. PiiDetector.Scan(text):
      - Regex match email → detected
      - Regex match SĐT → detected
   b. Return GuardrailResult { allowed: true, action: mask, violations: [pii_email, pii_phone] }
3. Nếu action = mask: thay PII bằng [REDACTED_EMAIL], [REDACTED_PHONE]
4. Message đã mask được gửi tới LLM
5. LLM response có thể chứa PII (nếu LLM nhớ)
6. SafetyGuardrails.CheckOutputAsync:
   a. PiiDetector.Scan(response)
   b. Nếu có PII: mask trước khi trả user
7. Audit log: "input PII masked: 2 violations"
```

### 4.6 Luồng Disaster Recovery

```
1. Backup service (chạy hàng ngày 2h sáng):
   a. pg_dump toàn bộ database → S3 (with encryption)
   b. WAL archive → S3
   c. MinIO incremental → S3
   d. Verify backup integrity
2. Cross-region replication:
   a. S3 replicate to DR region
   b. PostgreSQL streaming replication to DR
3. Khi disaster xảy ra:
   a. Alert: production down
   b. Runbook: initiate DR
   c. Spin up DR cluster
   d. Restore from latest backup
   e. Update DNS → DR endpoint
   f. Verify: smoke test
4. Post-mortem: cải thiện backup, automation
```

```sql
CREATE TABLE roles (

);
```

### 7.3 RLS Interceptor

```csharp
// RlsInterceptor.cs - EF Core interceptor tự động set tenant context
public class RlsInterceptor : DbCommandInterceptor
{
    private readonly ITenantContext _tenantContext;
    
    public override async ValueTask<InterceptionResult> CommandCreatingAsync(
        DbCommand command, CommandEventData eventData, InterceptionResult result, CancellationToken ct = default)
    {
        if (_tenantContext.TenantId.HasValue)
        {
            // Set PostgreSQL session variable
            await command.Connection.ExecuteAsync($"SET app.current_tenant_id = '{_tenantContext.TenantId}'", ct);
        }
        return result;
    }
}
```

### 9.3 Luồng Safety Guardrail

```
User gửi: "Cho tôi email admin là admin@company.com và số ĐT 0912345678"
                       │
                       ▼
SafetyMiddleware.CheckInputAsync:
  - PiiDetector.Scan(text)
    → Detected: email, phone
    → Severity: high
  - PromptInjectionDetector.Scan(text)
    → Not detected
  - Return GuardrailResult { allowed: true, action: mask, violations: 2 }
                       │
                       ▼
Nếu action = mask:
  - Sanitized: "Cho tôi email admin là [REDACTED_EMAIL] và số ĐT [REDACTED_PHONE]"
  - Log warning: "input PII masked"
  - Gửi sanitized input tới LLM
                       │
                       ▼
LLM response → SafetyMiddleware.CheckOutputAsync:
  - Output filter
  - PII detection
  - Hallucination check
                       │
                       ▼
Nếu response có PII (LLM nhớ):
  - Mask trước khi trả user
  - Log warning
```

### 9.4 Luồng HITL với Email

```
1. Agent step cần approval
2. HITLService:
   a. Tạo HITLRequest trong DB
   b. Tìm thông tin approver (user, manager)
   c. SendNotification:
      - Email qua SendGrid với link "Approve"/"Reject"
      - Slack (optional)
   d. Set timeout 7 ngày
3. User nhận email
4. User click "Approve" trong email:
   → Redirect → /webhook/hitl-response?requestId=xxx&action=approve&token=yyy
5. Backend verify token, update HITLRequest status=approved
6. Agent run resume
7. Step tiếp tục
```

### 9.5 Luồng Disaster Recovery

```
1. Production cluster down
2. Alert: PagerDuty page on-call
3. On-call verify: thật sự down (không phải false alarm)
4. Run DR runbook:
   a. Stop production traffic (update DNS)
   b. Promote DR cluster: scale up pods, point to latest backup
   c. Restore database từ latest backup (cross-region S3)
   d. Wait for sync (RPO ≤ 1 giờ)
   e. Verify health checks pass
   f. Update DNS → DR endpoint
   g. Notify stakeholders
5. RTO đạt: < 4 giờ
6. Post-mortem: cải thiện DR, automation
```

## Phụ lục A: Common Pitfalls

### A.1 RLS bypass qua superuser

**Vấn đề**: PostgreSQL superuser bypass RLS policies.

**Giải pháp**: 
- Dùng `FORCE ROW LEVEL SECURITY` để áp dụng cho cả superuser.
- Hoặc dùng non-superuser DB user cho application.

### A.2 OIDC state bị CSRF

**Vấn đề**: Attacker có thể inject state, lừa user login vào tenant của attacker.

**Giải pháp**: 
- State parameter chứa cryptographic nonce, lưu session.
- PKCE bắt buộc cho public client.
- Verify state khi callback.

### A.3 PII detection sai (false positive)

**Vấn đề**: Số "123456" trong query SQL bị nhận nhầm là SĐT.

**Giải pháp**: 
- Confidence threshold cao.
- Cho phép whitelist (vd: ID sản phẩm).
- Human review khi cần.

### A.4 Audit log storage cost cao

**Vấn đề**: Log mọi action → DB phình to.

**Giải pháp**: 
- Retention policy: 1 năm default.
- Archive old logs sang cold storage (S3 Glacier).
- Sampling cho high-volume events.

### A.5 K8s resource không đủ

**Vấn đề**: Pod OOMKilled khi load cao.

**Giải pháp**: 
- Set requests/limits hợp lý.
- HPA scale theo CPU + memory + custom metrics.
- Load test để xác định baseline.

### A.6 Vault unavailable → app không start

**Vấn đề**: App cần secrets từ Vault khi start, Vault down → app crash.

**Giải pháp**: 
- Cache secrets locally (encrypted) sau khi load đầu tiên.
- Fallback: cho phép env var override.
- Graceful degradation: log warning, dùng default.
