## 1. Tổng quan Phase 1

### 1.1 Tại sao là "Walking Skeleton"?

Walking Skeleton là phiên bản **tối giản nhất** của hệ thống, đi qua tất cả các layer (Frontend → API → Backend → AI Provider → Storage), nhưng mỗi layer chỉ làm **đúng 1 việc đơn giản nhất**.

**Lợi ích**:
- Chứng minh kiến trúc khả thi từ sớm.
- Phát hiện vấn đề tích hợp sớm (network, docker, port conflict...).
- Team có thể bắt đầu làm việc ngay, không cần đợi phase sau.
- Stakeholder thấy được sản phẩm chạy thật, không chỉ là slide.

### 1.2 Tóm tắt kỹ thuật

| Thành phần | Phase 1 |
|------------|---------|
| Backend | .NET 8 Web API + Minimal APIs (cho đơn giản, sau này có thể chuyển Controller) |
| Database | PostgreSQL 16 + pgvector (chỉ dùng table thường, pgvector chưa dùng) |
| Cache | Redis 7 (chỉ dùng để cache config, chưa cache LLM response) |
| LLM | Ollama local (chỉ 1 provider, model llama3.2:3b) |
| Auth | JWT HS256, 1 user, 1 tenant cứng trong config |
| Frontend | Next.js 14 + 1 trang chat đơn giản (text input + message list) |
| Container | Docker Compose cho PostgreSQL, Redis, Ollama, Backend, Frontend |
| Logging | Serilog → Console (JSON format) |
| Test | xUnit + FluentAssertions + Testcontainers |
| Docs | README, CHANGELOG, file phase này |

## 2. Phạm vi & Không phạm vi

### 2.1 Trong phạm vi (In Scope)

✅ Tạo solution .NET 8 với cấu trúc thư mục như Mục 5 trong MASTER_PLAN.

✅ Source generator / central package management (Directory.Packages.props).

✅ Platform.Core với:
- `Result<T>` pattern.
- `DomainException` base class.
- Common interfaces (`ITenantContext`, `IUserContext`).
- `ChatMessage`, `ChatRequest`, `ChatResponse`, `ChatDelta` (đặt ở Core để mọi provider dùng chung).

✅ Platform.Infrastructure:
- Serilog setup (Console JSON sink, có enrichers cho TraceId, TenantId).
- Options pattern binding.
- IConfiguration mở rộng (chưa cần Configuration Manager, dùng IConfiguration của .NET).

✅ Platform.Tenancy:
- `ITenantContext` interface.
- `TenantContext` implementation (đọc từ JWT claim).
- `ITenantResolver` interface + 1 implementation (đọc từ claim `tenantId`).

✅ Platform.Auth:
- `IUserContext` interface.
- `UserContext` implementation (đọc từ JWT claim).
- `IAuthService` interface + `JwtAuthService` (issue/validate JWT, password hash đơn giản với BCrypt).
- `IPasswordHasher` interface + implementation.
- `[Authorize]` attribute hoạt động.

✅ Platform.Providers.Abstractions:
- `ILLMProvider` interface.
- `ChatRequest`, `ChatResponse`, `ChatDelta`, `ChatMessage`, `ChatRole` enum.
- `ProviderMetadata` (ProviderId, SupportedModels, Capabilities).
- `ILLMProviderFactory` interface (tạo provider theo config).

✅ Platform.Providers.Ollama:
- `OllamaProvider` implement `ILLMProvider`.
- Hỗ trợ: ChatAsync, StreamChatAsync, GetCapabilities, HealthCheck.
- HttpClient qua `IHttpClientFactory` (typed client).
- Polly retry + circuit breaker.

✅ Platform.Providers.Router:
- `IProviderRouter` interface.
- `ProviderRouter` implementation: lúc này chỉ trả về Ollama provider (sẽ mở rộng ở Phase 2).
- Inject vào DI.

✅ Platform.Gateway (REST):
- `/api/v1/auth/login` - POST, body: `{email, password}` → trả JWT.
- `/api/v1/auth/me` - GET, lấy thông tin user hiện tại.
- `/api/v1/chat` - POST, body: `{message, sessionId?}` → trả response.
- `/api/v1/chat/stream` - POST, body: `{message, sessionId?}` → SSE streaming.
- `/api/v1/health` - GET, public, kiểm tra health backend + Ollama.
- `/swagger` - Swagger UI cho dev.

✅ Platform.Api (Host):
- `Program.cs` setup DI, middleware, OpenAPI, CORS, JWT.
- Configuration binding cho tất cả options.
- Background hosted service: warm up Ollama model khi start.
- Global exception handler (RFC 7807).
- OpenTelemetry setup cơ bản (tracing + metric).

✅ Chat Session & Message persistence:
- `ChatSession` entity (id, userId, title, createdAt).
- `ChatMessage` entity (id, sessionId, role, content, createdAt).
- EF Core migration.
- Auto-create session nếu chưa có.

✅ Frontend (Next.js):
- Trang `/login` - form đăng nhập.
- Trang `/chat` - danh sách session bên trái, message list bên phải, input box dưới cùng.
- Gọi API backend qua `fetch` với JWT trong header.
- Hiển thị streaming response (đọc SSE).
- Copy code button, markdown render cơ bản.

✅ Docker Compose:
- Service: `postgres`, `redis`, `ollama`, `backend`, `frontend`.
- Network internal.
- Volume cho data persistence.
- Health check cho mỗi service.

✅ Tests:
- Unit test: `JwtAuthService`, `OllamaProvider` (với mock HttpClient), `ChatSessionService`.
- Integration test: full flow login → chat → response, dùng Testcontainers cho PostgreSQL.

✅ Documentation:
- README.md (cách chạy, cấu trúc, scripts).
- CHANGELOG.md (v0.1.0).
- `docs/02.PHASES/01.MASTER_PLAN.md` và file phase này.
- `docs/04.RUNBOOKS/dev-setup.md`.

### 2.3 Interface được chốt ở Phase 1

Interface **BẮT BUỘC** giữ nguyên cho đến hết project (trừ khi có ADR phê duyệt thay đổi):

```csharp
// Trong Platform.Providers.Abstractions
public interface ILLMProvider
{
    string ProviderId { get; }
    IAsyncEnumerable<ChatDelta> StreamChatAsync(ChatRequest request, CancellationToken ct);
    Task<ChatResponse> ChatAsync(ChatRequest request, CancellationToken ct);
    ProviderCapabilities GetCapabilities(string modelId);
    Task<ProviderHealth> HealthCheckAsync(CancellationToken ct);
}

public record ChatRequest(
    string ModelId,
    IReadOnlyList<ChatMessage> Messages,
    ChatRequestOptions? Options = null,
    Guid? TenantId = null,
    string? TraceId = null
);

public record ChatRequestOptions(
    double Temperature = 0.7,
    int? MaxTokens = null,
    double? TopP = null,
    int? Seed = null,
    IReadOnlyList<ToolDescriptor>? Tools = null
);

public record ChatMessage(ChatRole Role, string Content);

public enum ChatRole { System, User, Assistant, Tool }

public record ChatResponse(
    string Content,
    string FinishReason,
    ChatUsage Usage,
    IReadOnlyList<ToolCall>? ToolCalls,
    string ProviderId,
    string ModelId,
    TimeSpan Latency
);

public record ChatDelta(string ContentDelta, string? FinishReason, string ProviderId);

public record ChatUsage(int PromptTokens, int CompletionTokens, int TotalTokens);

public record ProviderCapabilities(
    int MaxContextTokens,
    bool SupportsStreaming,
    bool SupportsFunctionCalling,
    bool SupportsVision,
    IReadOnlyList<string> SupportedLanguages
);

public record ProviderHealth(bool IsHealthy, string? Message, DateTime CheckedAt);
```

**Lưu ý**: Interface này được sử dụng xuyên suốt Phase 2-5. Phase 2 sẽ mở rộng thêm (StreamingChat → dùng IAsyncEnumerable<ChatDelta>, ToolCall sẽ được dùng thật). Phase 3-5 sẽ thêm vào interface nhưng **không sửa chữ ký các method cũ**.

## 3. Acceptance Criteria

Phase 1 hoàn thành khi **TẤT CẢ** các tiêu chí sau đạt:

### 3.1 Build & Runtime

- [ ] `dotnet restore` thành công cho tất cả project.
- [ ] `dotnet build` thành công, không có warning.
- [ ] `docker compose up` khởi động được 5 service (postgres, redis, ollama, backend, frontend) trong < 2 phút.
- [ ] Backend accessible tại `http://localhost:5000`, health endpoint trả 200 OK.
- [ ] Frontend accessible tại `http://localhost:3000`.
- [ ] Ollama accessible tại `http://localhost:11434`, model llama3.2:3b đã pull.

### 3.2 Functional

- [ ] Có thể đăng nhập với user mặc định (`admin@platform.local` / `admin123`).
- [ ] JWT token được issue và validate đúng.
- [ ] Trang chat sau khi login gọi được `/api/v1/chat` và nhận response.
- [ ] Streaming response hiển thị từng token một.
- [ ] Lịch sử chat được lưu vào PostgreSQL, có thể load lại khi refresh trang.
- [ ] Khi gọi không có JWT, backend trả 401.
- [ ] Khi gọi với JWT hết hạn, backend trả 401.
- [ ] Khi Ollama down, backend trả 503 với message rõ ràng.

### 3.3 Code Quality

- [ ] Code tuân thủ coding convention (Mục 5.1 MASTER_PLAN).
- [ ] Mỗi public class có XML doc comment.
- [ ] Mỗi public method có unit test.
- [ ] Integration test cho happy path của `/auth/login` và `/chat`.
- [ ] Test coverage ≥ 60% cho business logic (Auth, Provider, Session service).
- [ ] Không có secret hardcoded (đọc từ config/env).

### 3.4 Documentation

- [ ] README.md đầy đủ: prerequisites, setup, run, test, structure.
- [ ] CHANGELOG.md có entry v0.1.0.
- [ ] File phase này (02.PHASE_01_FOUNDATION.md) đã được tạo.
- [ ] Mỗi project có README riêng nếu cần.
- [ ] Swagger UI accessible tại `/swagger` và mô tả rõ ràng.

### 3.5 Observability

- [ ] Mỗi request có `traceId` log ở format JSON.
- [ ] Log chứa `tenantId`, `userId` (nếu authenticated), `requestPath`.
- [ ] Có OpenTelemetry trace cho HTTP request + Ollama call.
- [ ] Có metric: `http_requests_total`, `llm_request_duration_seconds`, `llm_tokens_total`.

```
1. User nhập message ở frontend
   ↓
2. Frontend: fetch POST /api/v1/chat/stream
   Headers: Authorization: Bearer <JWT>
   Body: { message, sessionId }
   ↓
3. Backend Middleware pipeline:
   - RequestLogging: log traceId, path, userId
   - AuthN: validate JWT, set UserContext
   - AuthZ: [Authorize] check
   - TenantResolver: set TenantContext
   ↓
4. ChatEndpoint.StreamChat():
   - Lấy userId, tenantId từ context
   - Lấy/create session qua ChatSessionService
   - Lưu user message vào DB
   - Lấy history messages từ DB
   - Build ChatRequest với history
   - Resolve provider qua ProviderRouter → OllamaProvider
   - Call OllamaProvider.StreamChatAsync()
   - Stream từng ChatDelta về frontend (SSE)
   - Tích lũy response content
   - Lưu assistant message vào DB khi stream xong
   - Emit metrics: tokens, latency
   ↓
5. Frontend nhận SSE, append từng chunk vào message bubble
   ↓
6. Kết thúc stream, hiển thị nút copy + feedback
```

## 7. Data Model Phase 1

### 7.1 Database Schema (PostgreSQL)

```sql
-- Bảng tenants: lưu thông tin tenant
-- Phase 1 chỉ tạo 1 tenant mặc định, sẽ mở rộng ở Phase 5
CREATE TABLE tenants (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name            VARCHAR(200) NOT NULL,
    slug            VARCHAR(100) NOT NULL UNIQUE,
    status          VARCHAR(20) NOT NULL DEFAULT 'active',
    settings        JSONB,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Bảng users: lưu user
CREATE TABLE users (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    email           VARCHAR(255) NOT NULL,
    password_hash   VARCHAR(255) NOT NULL,
    display_name    VARCHAR(200) NOT NULL,
    role            VARCHAR(50) NOT NULL DEFAULT 'user', -- 'admin' | 'user' (Phase 1 chỉ check 'admin')
    status          VARCHAR(20) NOT NULL DEFAULT 'active',
    last_login_at   TIMESTAMPTZ,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE(tenant_id, email)
);

CREATE INDEX idx_users_tenant ON users(tenant_id);

-- Bảng chat_sessions: lưu session chat
CREATE TABLE chat_sessions (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    user_id         UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title           VARCHAR(500) NOT NULL DEFAULT 'New Chat',
    metadata        JSONB,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    deleted_at      TIMESTAMPTZ
);

CREATE INDEX idx_chat_sessions_user ON chat_sessions(user_id, updated_at DESC);
CREATE INDEX idx_chat_sessions_tenant ON chat_sessions(tenant_id);

-- Bảng chat_messages: lưu từng message trong session
CREATE TABLE chat_messages (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id       UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    session_id      UUID NOT NULL REFERENCES chat_sessions(id) ON DELETE CASCADE,
    role            VARCHAR(20) NOT NULL,  -- 'system' | 'user' | 'assistant' | 'tool'
    content         TEXT NOT NULL,
    metadata        JSONB,                -- tokens, latency, model, etc.
```

## 9. Luồng End-to-End (Happy Path)

### 9.1 Luồng Login

```
1. User mở browser → http://localhost:3000
2. Frontend redirect → /login
3. User nhập email + password
4. Frontend: fetch POST /api/v1/auth/login
5. Backend AuthEndpoints.Login():
   a. Validate request body
   b. Tìm user theo email
   c. Verify password bằng BCrypt
   d. Tạo JWT với claim: sub=userId, tenantId=tenantId, role=role
   e. Update user.LastLoginAt
   f. Trả LoginResponse
6. Frontend: lưu token vào localStorage, redirect → /chat
```

### 9.2 Luồng Chat (Streaming)

```
1. User ở /chat, gõ message, bấm Enter
2. Frontend useStreamChat hook:
   a. Gọi fetch POST /api/v1/chat/stream với JWT
   b. Mở SSE stream
   c. Append từng chunk vào message bubble
3. Backend ChatEndpoints.StreamChat():
   a. AuthN middleware: validate JWT, set UserContext
   b. TenantMiddleware: set TenantContext
   c. Lấy userId, tenantId từ context
   d. ChatSessionService: get or create session
   e. Persist user message vào DB
   f. Load history (last 20 messages)
   g. Build ChatRequest với messages
   h. ProviderRouter.SelectLLMProviderAsync() → OllamaProvider
   i. OllamaProvider.StreamChatAsync() trả IAsyncEnumerable<ChatDelta>
   j. Mỗi delta: ghi vào SSE response, flush
   k. Sau khi stream xong: accumulate content
   l. Persist assistant message vào DB
   m. Emit metrics
4. SSE gửi về frontend:
   - "event: chunk" cho mỗi delta
   - "event: done" khi kết thúc (kèm usage)
5. Frontend hiển thị message hoàn chỉnh
```

## Phụ lục A: Common Pitfalls & Solutions

### A.1 Ollama chậm ở request đầu tiên

**Vấn đề**: Request đầu tiên đến Ollama phải load model vào memory → mất 5-30s.

**Giải pháp**: `OllamaWarmupService` (IHostedService) chạy khi backend start, gọi Ollama với prompt ngắn để warm up model.

### A.2 EF Core migration fail khi container start

**Vấn đề**: Backend start trước khi PostgreSQL ready.

**Giải pháp**: `depends_on: condition: service_healthy` trong docker-compose, retry connection với Polly trong Program.cs.

### A.3 CORS issue khi frontend gọi API

**Vấn đề**: Browser block request cross-origin.

**Giải pháp**: CORS policy trong Program.cs allow `http://localhost:3000` (dev) hoặc `*.platform.com` (prod).

### A.4 JWT không lưu được ở frontend

**Vấn đề**: localStorage có thể bị XSS, cookie có thể bị CSRF.

**Giải pháp Phase 1**: dùng localStorage (đơn giản, dễ demo). Phase 5 sẽ chuyển sang httpOnly cookie + CSRF token.

### A.5 Streaming response bị buffer

**Vấn đề**: ASP.NET Core buffer response, không flush ngay.

**Giải pháp**:
- Dùng `IAsyncEnumerable<T>` + `Response.BodyWriter` + `FlushAsync()`.
- Set `Response.ContentType = "text/event-stream"`.
- Set `Response.Headers["Cache-Control"] = "no-cache"`.
- Set `Response.Headers["X-Accel-Buffering"] = "no"` (cho nginx).
